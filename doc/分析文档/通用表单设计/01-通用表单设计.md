# 通用表单设计

物理表走 `SysDatabase`，字段进 `hr_ui_field_def`，排版走已有 `HrUiLayout`，下拉码走 `code_mstr`。四层用 `FieldKey` / `CodeField` 关联。展示名由后端按当前文化解析，前端只绑 `field` + `label`。一期只做 `hrEmp`。

相关：[`界面报表定义`](../界面报表定义/README.md)、[`代码类设置多语言分析`](../代码类设置多语言分析/README.md)、[`人员资料`](../人员资料/README.md)。

---

## 1. 为什么分层

旧系统（PowerBuilder 风格《表设计》）是四屏一条龙：系统表清单 → 单表字段设计（含「表重建」）→ 报表字段显示（宽、占列、`ddwName`）→ 行上挖掘代码维护。权限、多语言、已落地的模块布局都被揉在一页里。

本仓库拆开：

| 旧屏 | 落点 |
|------|------|
| 表注册 / 表设计 / 表重建 | 系统「库管理」`SysDatabase`。HR 菜单只同步进元数据，不开放重建、删表 |
| 报表字段显示 | 已有 `hr_ui_layout`：按模块 + 场景 + 系统默认/个人方案 |
| 代码挖掘 | 字段池只存 `CodeField`；码值在「人事代码设置」页和定义页弹窗维护 |
| 宽表 English 列 | 翻译表 + culture 回退，不加 `label_en` 这类列 |

不复用代码生成器表做运行时字段池，也不另起 `SYS_COLUMN*` 或 `v-form-designer` 第二套设计器。布局不能在没有实体/API 字段时单独造出可落库列。EAV / JSON 动态列本期不做。

## 2. 已落地（布局层，2026-10-13）

人事资料已具备列表/表单**定义页**，列表已消费生效布局。字段池仍是 `HrUiLayoutService.GetPool` 硬编码，表单编辑页尚未消费 form Effective。下面是现状，后续阶段在此之上加字段池和多语言，不另起布局表。

### 2.2 方案模型

| 概念 | 规则 |
|------|------|
| `ModuleCode` | 如 `hrEmp` |
| `Scene` | `list` 列表列；`form` 表单 |
| 系统默认 | `is_default=1` 且 `owner_user_id` 为空；同模块同场景一条 |
| 个人方案 | 每用户每场景一套，保存整单覆盖 |
| 生效顺序 | 当前用户个人方案 → 系统默认 → 无库方案时 Builtin（该场景字段池全部可见） |

`hr_ui_layout`：`module_code`、`scene`、`name`、`is_default`、`owner_user_id`、`version`。  
`hr_ui_layout_field`：`field_key`、`db_column`、`label`、`sort_no`、`visible`、`width_px`、`span_slots`、`group_code`、`control_type`、`required`、`readonly`。

已有 API（路径保持）：

| API | 作用 |
|-----|------|
| `GET hrUiLayout/effective` | 当前生效方案 |
| `GET hrUiLayout/default` | 系统默认 |
| `GET hrUiLayout/fieldPool` | 字段池 |
| `POST hrUiLayout/saveMy` / `resetMy` | 个人方案保存 / 删除后回退 |
| `POST hrUiLayout/saveDefault` | 管理员保存系统默认 |

### 2.3 栅格与默认列

表单一行 6 格。`spanSlots` 取 1～6，Element 栅格 `span = spanSlots × 4`（定义页预览与后端校验已按此实现）。列表用 `widthPx`，不用占位格。操作列、选择列由页面固定，不进布局。

列表默认 12 列：工号、姓名、部门（`ccDesc`）、性别、年龄、联系电话、职务、岗位、公司入职日、人员类别、薪酬类别、状态。  
表单约 33 个字段，分组 `basic` / `job`。长文本（证件、地址）默认 2 格；`empPic` 为照片；`ccCode` 为组织级联；`age` 只读计算。工号、姓名锁定，保存时服务端强制补回。完整种子以 `20261013` 布局 SQL 为准。

列表排序：请求带 `field` / `order` / `descStr: 'desc'`，后端 `OrderBuilder`。本地键 `localPageParam:hrEmp`。可排序列必须是池内且接口支持的字段；本地记忆的排序列被隐藏时回退 `empId`。

## 3. 建设目标与铁律

### 3.1 要做成的事

1. **字段池表驱动**：`hr_ui_field_def` 替换硬编码 `GetPool`。  
2. **场景适用**：`hr_ui_field_scene` 决定字段能否进入某场景设计器。默认显示哪些列仍由布局 / Builtin 决定。  
3. **布局只排版**：顺序、显隐、列宽、占位、分组、必填、只读。`ControlType` 与 `CodeField` 只存在字段池，Effective 合并时以池为准。  
4. **代码绑定**：池上的 `CodeField` → `GetCodeList`。P3 同时交付完整「人事代码设置」页和定义页弹窗。读接口放在 `HrCodeMstrService`，`HrOrgService.GetCodeList` 只转发。  
5. **多语言**：翻译表 + 当前文化 + zh-CN 回退。布局译文按语言稀疏覆盖，没有译文行就继承池。  
6. **运行时**：列表保持现消费；P6 表单用「字段渲染器注册表 + 通用控件」消费 form Effective。

### 3.2 明确不做

| 禁止 | 说明 |
|------|------|
| EAV / JSON 动态列 | 无实体字段的配置不落库 |
| 业务角色表重建 | DDL 复用 SysDatabase；HR 菜单禁止重建/删表 |
| 平行 `SYS_COLUMN*` | 不另起与 `hr_ui_*` 重复的体系 |
| 宽表多语列 | 不用 `label_en` / `label_th` 作正式方案 |
| `ddwName` 一等公民 | 仅兼容期映射到 `CodeField` |
| 可运营码进 vue-i18n | 人事码描述走 `code_mstr_lang`；菜单按钮仍走 vue-i18n |
| `IsUserTuned` | 同步不靠总开关；插入之后不回写显示名、控件、代码绑定 |
| `IsLabelOverridden` | 某一语言有布局译文行即该语言被覆盖 |
| 池上的场景布尔列 | 不用 `list_visible` / `form_visible` / scene_mask |
| 布局自持控件定义 | `control_type`、`code_field` 不以布局表为来源 |
| 长期双份字段池 | `HrUi:UseDbFieldPool` 只留到 P1 验收，通过后删除硬编码 `GetPool` |
| 解析器自读 `Accept-Language` | 只读系统已 `SetCulture` 的当前文化 |

### 3.3 一期范围

| 项 | 值 |
|----|-----|
| 模块 | 仅 `hrEmp`，主表 `h_emp_mstr` |
| 场景 | `list` / `form` |
| 主语言 | `zh-CN` |
| culture | `zh-CN` / `zh-TW` / `en` / `th` / `vi` |
| 库 | 实体挂 `[Tenant(hr_2025)]`。现状默认库与 `hr_2025` 连同一物理库 `ehr`；`hr_2025` 是连接标识，不是独立库 |

## 4. 架构

```text
┌──────────────┐    FieldKey / CodeField    ┌──────────────────────┐
│ 物理结构      │ ─────────────────────────► │ 字段元数据池          │
│ SysDatabase  │   Sync 只碰 origin=physical │ hr_ui_field_def      │
└──────────────┘                            │ + lang + field_scene │
                                            └──────────┬───────────┘
                                                       │ 场景适用 + 白名单
                                                       ▼
┌──────────────┐    GetCodeList(CodeField)  ┌──────────────────────┐
│ 代码类        │ ◄──────────────────────── │ 布局                  │
│ code_mstr    │   控件/码类从池合并         │ 只存排版 + 稀疏译文   │
│ (+_lang)     │                            └──────────┬───────────┘
└──────────────┘                                       │ Effective
                          横切解析 Label / 码描述        ▼
                                            ┌──────────────────────┐
                                            │ 运行时                │
                                            │ 注册表优先，其余按控件 │
                                            └──────────────────────┘
```

UI 壳（菜单、按钮、固定文案）走 vue-i18n / `Lang.*.json`，不进字段元数据。

| 模块 | 职责 | 一期要点 |
|------|------|----------|
| M1 模块注册 | ModuleCode / 主表 / EnsureModule | 常量 Catalog；P7 可选落表 |
| M2 物理同步源 | GetColumnList；禁重建 | 仅供 Sync；不加业务 DDL API |
| M3 字段池 | CRUD、Sync、QueryPool、场景适用 | P1 建表+seed+读表；P3 维护页 |
| M4 布局 | Effective / Save / 排版 | P1 同源池；P3 只读 CodeField；P5 稀疏译文 |
| M5 代码绑定 | CodeField、码值维护、GetCodeList | P3 完整页+弹窗；P4 只加译文 |
| M6 多语言 | Resolver 回退链 | P2 池译；P4 码译；P5 布局译 |
| M7 运行时 | 列/表单项映射、排序、渲染器 | P1 列表回归；P6 表单 |

关联键：

| 键 | 规则 |
|----|------|
| `ModuleCode` | `^[a-zA-Z][a-zA-Z0-9_]*$`，≤64。如 `hrEmp` |
| `FieldKey` | camelCase；同模块唯一；与 emp DTO 对齐；**一旦写入，同步不得改名** |
| `DbColumn` | 物理列；`computed` / `lookup` 为空 |
| `Origin` | `physical` / `computed` / `lookup` |
| `CodeField` | 只在字段池；对应 `code_mstr.code_field`；可空 |
| `Scene` | 适用性在 `hr_ui_field_scene`；一期仅 `list` / `form` |
| 存库业务值 | `code_value`，不存当前语言显示名 |

Catalog 一期内存：`hrEmp → MainTable=h_emp_mstr, Scenes=[list,form], Name=人事资料`。`EnsureModule` 供 Layout / FieldDef / Code 写入口共用。未知模块的读接口也拒绝。

### 4.1 Label 优先级

```text
1. layout_field_lang[culture] 有非空行
2. field_def_lang[culture] 有非空行
3. hr_ui_field_def.label（池主语言 zh-CN）
4. FieldKey
```

- 布局主表 `label` **不参与**解析。保存时该列写池主语言，只为兼容旧列。  
- 要覆盖某一语言（含 zh-CN），就在 `hr_ui_layout_field_lang` 写该 culture 一行。没有行就继承池。  
- 「恢复池默认」删除该布局字段的译文行（可按当前语言或全部语言）。  
- 运行时禁止用字符串比较判断是否改名。P5 一次性迁移：已有布局字段 `Trim` 后与池主语言不同的，插入 `culture=zh-CN` 译文行。  
- 因此池有「工号 / Emp No」、布局只覆盖中文为「员工编号」时，切到英文仍显示 Emp No。

读路径多语言失败：回退主语言，不抛错留白。禁止按字段逐条查库。

### 4.2 码下拉

```text
value = code_value（存库不变）
label = "{code_value} {code_desc}"   // 描述经 culture 解析；描述回退为码值本身则不重复拼接
```

现网 `GetCodeList` 已按此拼接。P4 只替换描述段来源，不改格式，前端不再二次拼接。

### 4.3 Effective 合并

| 属性 | 来源 |
|------|------|
| 顺序、显隐、列宽、占位、分组、必填、只读 | 布局字段 |
| `ControlType`、`CodeField`、`DataType`、`Sortable`、`Locked`、`Origin` | 字段池 |
| `Label` | §4.1 |
| `IsStale` | 池中不存在、未启用，或不在该场景适用表 |

保存时忽略客户端传来的控件类型和代码绑定。`hr_ui_layout_field.control_type` 列保留，写入池上的值，避免旧读者读到过期控件。不往布局表新增 `code_field`。

校验：去重 FieldKey；必须属于该场景 `QueryPool` 且启用、在池内；锁定字段缺失则强制插回；`form` 的 `spanSlots` 必须在 1～6；字段列表不能为空。`IsStale` 行允许留在已存布局里，GetEffective 标出，运行时不渲染（列表建议隐藏并告警）。

## 5. 数据模型

### 5.1 增量表

| 表 | 阶段 | 说明 |
|----|------|------|
| `hr_ui_field_def` | P1 | 字段池主表，含 `origin` |
| `hr_ui_field_scene` | P1 | 场景适用；PK=`module_code+field_key+scene` |
| `hr_ui_field_def_lang` | P2 | 池 Label；PK=`module_code+field_key+culture` |
| `code_mstr_lang` | P4 | 码描述；PK=`code_field+code_value+culture` |
| `hr_ui_layout_field_lang` | P5 | PK=`layout_field_id+culture`；含 zh-CN 覆盖行 |
| `hr_ui_module` | P7 可选 | 模块注册表 |

不新增 `is_user_tuned`、`is_label_overridden`、`list_visible`、`form_visible`。  
已有 `hr_ui_layout`、`hr_ui_layout_field`、`code_mstr` 不改主模型。

### 5.2 `hr_ui_field_def`

`module_code`、`field_key`、`origin`、`db_column`、`table_name`、`label`、`data_type`、`is_nullable`、`control_type`、`code_field`、`default_width_px`、`default_span_slots`（默认 1）、`group_code`、`is_in_pool`、`sortable`、`required`、`readonly`、`locked`、`sort_no`、`enabled`，以及 EntityBase 常规字段。

| `origin` | 含义 | 一期例子 |
|----------|------|----------|
| `physical` | 主表物理列 | `empId`、`empName`、`empPic` |
| `computed` | 计算字段，无物理列 | `age` |
| `lookup` | 关联展示，无本表列 | `ccDesc` |

索引：`(module_code, field_key)` 过滤唯一（`is_delete=0`）。锁定字段必须 `is_in_pool=true`。`ControlType=select` 且 `CodeField` 为空时允许保存，定义页提示。

`hr_ui_field_def_lang` 用业务键复合主键，便于种子。

### 5.3 场景适用

设计器能否选用该字段，与布局上的 `visible`（当前方案是否显示）分开。

P1 种子复现现 `GetPool` 差集：列表排除证件、地址、照片、`ccCode` 等；表单排除 `ccDesc`。无数据库方案时，Builtin 将该场景适用字段全部视为可见，因此默认列与现网一致，不必再往 `hr_ui_layout` 插一套内置方案（避免覆盖已保存布局）。

以后若「可选字段」多于「默认显示」，只改系统默认布局的 `visible`，不改场景表。

一期字段并集（与现池一致，同步不得重算这些键）：

```text
empId, empName, empCard, empCardOverdate, empCardDate, empCardLimit,
empSex, empBirth, age, empRgt, empNation, empProvince, empResidence,
empMarry, empAddr, empHome, empAddrter, empPic,
ccCode, ccDesc, dutyId, postId, empWorkDate, empInDateGroup, empInDate,
empBegDate, empTryDate, empFromDate, empLongmon, empKqIndate, empKqLeaDate,
empType, empSal, empState
```

### 5.4 同步（仅 `origin=physical`）

匹配键：同模块已有行的 `db_column`（忽略大小写）。已有行的 `field_key` 永不重算。

新列首次生成 FieldKey：已是 camelCase 则沿用，否则 snake/pascal 转 camelCase，与 emp DTO 对齐（`emp_id` → `empId`）；冲突时后缀 `_2`。P1 不提供改 FieldKey 的界面。P1 种子必须使用现网已有键。

1. 库中新列且没有对应行 → 插入，`origin=physical`。显示名、控件、代码绑定只在插入时给默认值。  
2. 已有物理行 → 只更新 `data_type`、`is_nullable`、`table_name`。不写 `label`、`control_type`、`code_field`、`field_key`。  
3. 物理列消失 → 该行 `enabled=false`。不级联删布局；Effective 标 `IsStale`。列重新出现 → `enabled=true`，仍不改显示名、控件、代码绑定。  
4. `computed` / `lookup`（以及 `db_column` 为空的行）→ 同步完全不碰。

返回：`inserted`、`structuralUpdated`、`disabled`、`reenabled`、`warnings`。没有 `skippedTuned`。

### 5.5 SQL 存放

新稿放入 `doc/sql/{yyyy-MM-dd}/`（按当天日期目录，不写 `doc/sql` 根或 `seed/`、`hr-layout/` 等历史目录）。

```text
hr_ui_field_def.sql
hr_ui_field_scene.sql
hr_ui_field_def_seed_hrEmp.sql
hr_ui_field_scene_seed_hrEmp.sql
hr_ui_field_def_lang.sql          # P2
code_mstr_lang.sql                # P4
hr_ui_layout_field_lang.sql       # P5
```

P1 配置项 `HrUi:UseDbFieldPool`，默认 true。false 时读路径回退硬编码 `GetPool`。对比验收通过后删除该开关和硬编码方法。

### 5.6 码值主键变更

`code_mstr` 主键是 `(code_field, code_value)`。修改 `code_value` 时，同一事务内把 `code_mstr_lang` 中相同 `code_field + 旧 code_value` 的行改到新码值。

### 6.2 API

| 阶段 | API | 说明 |
|------|-----|------|
| P1 | `GET hrUiLayout/fieldPool` | 读表 + 场景适用；`codeField` 来自池 |
| P1 | 既有 layout GET/POST | 白名单同源 QueryPool；合并控件与码类 |
| P2 | （无新路径） | Pool/Effective 的 Label 经 Resolver |
| P2/P3 | `hrUiFieldDef/page\|detail\|update\|syncFromDb\|langList\|saveLang` | 维护 |
| P3 | `hrCodeMstr/page\|save\|delete` | 码值（主语言） |
| P3 | `hrOrg/codeList` | 转发，路径与响应形状不变 |
| P4 | `hrCodeMstr/langList\|saveLang` | 只解析描述段 |
| P5 | 布局 Save 接受 `Labels[]` | 空文案删除该语言行 |
| P7 | 可选 `hrUiModule/list` | |

字段元数据分页：入参继承 `BasePageInput`（`Field` / `Order` / `DescStr`），查询链末端 `.OrderBuilder(input)`。筛选 `ModuleCode`（必填）、`Keyword`（field_key / label / db_column）、可选 Enabled / IsInPool / ControlType。默认排序 `sortNo` asc。

人事代码维护页默认排序 `codeValue` asc。`code_sort` 在现表是字符串，维护页不拿它当默认数字序。下拉 `GetCodeList` 仍按现网 `code_sort`、再 `code_value`。

Update 可改 Label / DataType / ControlType / CodeField / Origin / 宽与占位 / 分组 / 是否入池 / 可排序 / 必填 / 只读 / 锁定 / 序号 / 启用。Label 必填且 ≤256。不存在 `IsUserTuned`。

`POST hrUiFieldDef/syncFromDb`：`{ moduleCode }` → `{ inserted, structuralUpdated, disabled, reenabled, warnings[] }`。

布局 DTO 增加：`CodeField?`、`Origin?`、`IsStale?`、`DataType?`（均来自池）；保存入参 `Labels?: { culture, label }[]`。

### 6.7 Resolver

## 7. 分期

```text
P1 ──► P2 ──► P5
 │       │
 ├──► P3 ──► P4 ──► P6 ──► P7
 │
 └──► 可选受控加列（晚于 P3）
```

| 阶段 | 交付 | 参考人天 | 可独立上线 |
|------|------|----------|------------|
| P1 | 池表+场景表+seed；GetPool 读表；验收后删除硬编码 | 2～3 | 删除硬编码之后 |
| P2 | `field_def_lang`；Pool/Effective 按当前文化 | 1～2 | 是 |
| P3 | 元数据页+Sync；布局只读 CodeField；完整码值页+弹窗 | 4～6 | 是 |
| P4 | `code_mstr_lang`；描述段随文化变化 | 1～2 | 是 |
| P5 | `layout_field_lang` + 定义页按语言覆盖 | 2～3 | 是 |
| P6 | 渲染器注册表 + editEmp | 3～5 | 是（建议开关） |
| P7 | 第二模块 + 可选 `hr_ui_module` | 视模块 | 是 |
| 可选 | 受控 AddColumn 向导 | 2+ | 单独评估 |

增量原则：P1 前端几乎不改，只回归 emp 列表。P2/P4/P5 响应仍返回 `label` 字符串，只是内容随语言变。P6 失败回退静态表单。

物理就绪的三种方式：存量表只同步（默认）；授权角色 `AddColumn` 后同步（可选，晚于 P3）；全新表仍要实体/DTO/API，布局不能单独扩出可持久化列。

## 9. 验收与风险

| 阶段 | 必测 |
|------|------|
| P1 | list/form 的 FieldKey 与旧 GetPool 一致；`age`/`ccDesc` 来源正确；emp 列头/顺序/宽不变；仓库不再保留硬编码 GetPool |
| P2 | `en` 有译文则为英文；缺译回退；集合不变 |
| P3 | 再次同步不改已有 Label/ControlType/CodeField；计算/关联列仍启用；新列会插入；码值页按 codeValue 排序；弹窗按 code_field 过滤 |
| P4 | 单次拼接；`en` 只变描述；改 code_value 后译文跟着走 |
| P5 | 只写布局中文时英文仍吃池译；无布局行则继承池；恢复默认回到池文案 |
| P6 | formDef 顺序/占位进入编辑页；四个注册字段走原组件；select 存 code_value |
| 持续 | 列表 `field`/`order`/`descStr` + OrderBuilder；Local 记忆；非法字段保存被拒绝；重置恢复系统默认；锁定字段无法删除 |

| 风险 | 缓解 |
|------|------|
| Seed ≠ 硬编码池，emp 列丢失或多余 | 种子从 GetPool 字面量导出 + 对比测试；验收前可关 `UseDbFieldPool` |
| 同步关掉计算列或回写文案 | `origin` 隔离；单测覆盖 `age`、`ccDesc` |
| Label 解析 N+1 | 批量 IN |
| 只覆盖中文布局名挡住英文池译 | 无该语言布局行必须继承池 |
| 误绑 CodeField | 只在元数据页可改；布局只读 |
| 过早开放 DDL | 默认关闭；菜单权限隔离 |
| 表单漏注册特殊字段 | 注册表白名单 + 回退静态表单 |
| 前端再拼一次码描述 | P4 保持现有拼接函数，只换描述来源 |
| 日期列过窄 | 列表设宽度下限；表单长字段默认 span≥2 |
| 配置被清空白屏 | 前端内置兜底 columns / schema |
| 个人方案过多 | 每用户每场景只保留一套 |

| 决策 | 结论 | 日期 |
|------|------|------|
| 首期场景 | 先 list，后 form | 2026-10-12 |

| 存储 | 独立 `hr_ui_layout*`，不复用代码生成表 | 2026-10-12 |
