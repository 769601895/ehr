# 查找数据源可配与多语言

> 日期：2026-10-28  
> 状态：已定稿（待实施）  
> 相关：`01-通用表单设计.md`、`../代码类设置多语言分析/01-multilang-analysis.md`

## 1. 目标

字段池下拉除绑定 `code_mstr`（代码类）外，可后台配置绑定**任意 HR 主档表**（岗位、以后 A/B/C/D…），加表**零改引擎代码**；选项 Label 支持多语言，缺译文回退主显示列。

## 2. 决策摘要

| 项 | 决定 |
|----|------|
| 方案 | 后台可配数据源（非代码登记表） |
| 过滤 | 第一期仅固定常用条件 |
| 多语言 | 与岗位一起上；数据源可配翻译表；解析对齐 `ResolveCodeDesc` |
| 与代码类关系 | `lookup_source` 与 `code_field` 互斥 |

## 3. 数据模型

### 3.1 `hr_lookup_def`（查找数据源）

| 列 | 类型 | 说明 |
|----|------|------|
| Id | bigint PK | EntityBase |
| code | nvarchar(64) UK | 编码，如 `hrPost`；字段池引用 |
| name | nvarchar(100) | 显示名 |
| table_name | nvarchar(128) | 主表，如 `hr_post` |
| value_column | nvarchar(64) | 存库值列，如 `post_code` |
| label_column | nvarchar(64) | 主语言显示列，如 `post_name` |
| order_column | nvarchar(64) null | 排序列；空则用 value_column |
| filter_use_is_delete | bit | 默认 1：追加 `IsDelete=0` |
| filter_enabled_column | nvarchar(64) null | 启用列，如 `status` |
| filter_enabled_value | nvarchar(64) null | 启用值，如 `Active` |
| filter_equal_column | nvarchar(64) null | 可选等值列 |
| filter_equal_value | nvarchar(128) null | 等值 |
| lang_table | nvarchar(128) null | 翻译表，如 `hr_post_lang`；空=单语 |
| lang_value_column | nvarchar(64) null | 译文表值列，默认同 value_column 名 |
| lang_culture_column | nvarchar(64) null | 默认 `culture` |
| lang_label_column | nvarchar(64) null | 译文列，如 `post_name` |
| maintain_path | nvarchar(256) null | 前端维护路由，如 `/sysCode/hrPost` |
| enabled | bit | 停用后不可选、运行时返回空列表 |
| remark | nvarchar(256) null | |
| + EntityBase 审计/软删 | | |

标识符（表名/列名）运行时校验：`^[A-Za-z_][A-Za-z0-9_]*$`，仅查 HR 库（`HrDbConfigId`）。

### 3.2 `hr_post_lang`（岗位译文）

| 列 | 说明 |
|----|------|
| post_code | PK，对应 `hr_post.post_code` |
| culture | PK，如 `zh-CN` / `en` |
| post_name | 译文 |

改 `post_code` 时同事务迁移译文行（对齐 `code_mstr`）。

### 3.3 `hr_ui_field_def`

新增 `lookup_source` nvarchar(64) null → 填 `hr_lookup_def.code`。  
保存校验：`lookup_source` 与 `code_field` 不可同时有值。

## 4. API

| 接口 | 说明 |
|------|------|
| `hrLookupDef` CRUD / Page | 数据源维护；排序 `OrderBuilder` |
| `hrLookupDef/listEnabled` | 字段元数据下拉用 |
| `hrLookupDef/getOptions?source=` | 统一选项：`{ value, label, text }[]`；按 `HrUiCulture.Current()` 解析 Label |
| `hrPost/langList` / `saveLang` | 对齐 `hrCodeMstr` |
| 字段 Effective / GetPool | 透出 `lookupSource` |

`GetOptions` 逻辑：读启用定义 → 白名单拼 SELECT → 主表行 → 若配置了 lang 表则按 culture 批量取译文 → `HrUiI18nResolver.ResolveCodeDesc(value, mainLabel, culture, map)`。

## 5. 前端

| 页 | 改动 |
|----|------|
| 新：查找数据源设置 | 列表+编辑（含过滤勾选、翻译表字段、维护路由） |
| 字段元数据 | 「数据源」下拉（listEnabled）；与代码类互斥；有 maintain_path 则可跳转 |
| 岗位代码设置 | 行操作增加多语言弹窗（同代码类） |
| emp 表单/列表 | 有 `lookupSource` 走 `getOptions`；有 `codeField` 仍走 `GetCodeList` |

## 6. 种子

- `hr_lookup_def`：`hrPost` → `hr_post` / `post_code` / `post_name`，过滤 IsDelete + status=Active，lang=`hr_post_lang`，maintain=`/sysCode/hrPost`
- `hrEmp.postId`：`lookup_source=hrPost`，清空 `code_field`（若曾误绑）
- 菜单：系统代码下「查找数据源设置」+ 角色授权

## 7. 非目标（第一期）

- 任意 SQL / AND-OR 复杂条件
- 跨库表、存储过程
- 职务等其它主档（仅种子岗位；加表只配 `hr_lookup_def` + 可选 `*_lang`）

## 8. 验收

- [ ] 后台可新增数据源指向某表，字段池选中后表单下拉有选项
- [ ] 切语言后岗位 Label 变（有译文时）；无译文回退 `post_name`
- [ ] `code_field` 与 `lookup_source` 互斥校验生效
- [ ] 非法表名/列名被拒绝；停用数据源后选项为空
