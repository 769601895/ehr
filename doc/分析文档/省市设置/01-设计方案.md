> 会话确认稿。实现前须产品确认本文；确认后再出实施计划。

## 1. 意图与背景

在「系统代码设置」下新增**可维护的省市主数据**，初始化中国省→市两级数据，供后续员工**籍贯**级联选用。

现有能力对照：

| 现状 | 说明 |
|------|------|
| `SysRegion`（系统 → 行政区划） | 多级树 + 云端同步，偏平台区划，不适合当人事籍贯代码源 |
| `HrEmployee.EmpProvince` | 自由文本，本期**不改** |
| 「系统代码设置」已有模块 | 如岗位代码 `hr_post`，本期对齐其菜单/CRUD/状态风格 |

**选型（已确认）：新建 HR 省市表，不复用 `SysRegion`。**

## 2. 目标 / 非目标

### 目标

- 菜单挂在「系统代码设置」（`SysMenu.Id = 1300000000206`）下，标题：**省市设置**

- 初始化中国省级 + 地级市（含直辖市同名市节点、港澳台省级）
- 提供下拉/级联用只读接口（`List` / `ListByProvince`），方便二期接籍贯
- 列表支持服务端排序（`OrderBuilder` + 列头 `sortable`）

### 非目标（本期不做）

- 初始化灌到区县却标成「只做到市」

## 3. 业务规则

1. **两级：** 省（含直辖市、自治区、特别行政区）→ 市（地级市；直辖市下挂与省**同名**市节点，如 北京市 → 北京市）。
2. **编码：** 国标 6 位行政区划码  
   - 省：后四位 `0000`（如 `110000` 北京市、`440000` 广东省）  
   - 市：地级码（如 `440300` 深圳市）  
   - 直辖市同名市：`city_code = xx0100`（如 `110100`），`city_name = 北京市`（显示同名市；避免与省码冲突）  
   - `city_code` 全局唯一，便于二期员工只存市码再反查省  
3. **状态：** `Active` / `Inactive`；停用省在级联下拉中默认不出现（维护页仍可查）。  
4. **删除：** 软删；省下仍有未删除市则禁止删省。  
5. **港澳台：** 作省级纳入；市挂同名节点（台湾可挂常用地级清单，种子内固定一版）。  
6. **种子市范围：** 仅地级市 / 地区 / 盟 / 自治州等「地级」单位 + 直辖市同名市；不灌区县、不灌乡级。

## 4. 数据模型

库：与 `hr_post` 相同 HR 库（`ApplicationConst.HrDbConfigId`）。

### 4.1 `hr_province` 省

| 列 | 类型 | 说明 |
|----|------|------|
| Id | bigint PK | 雪花 |
| province_code | nvarchar(12) | 省代码，未删唯一 |
| province_name | nvarchar(50) | 省名称 |
| order_no | int | 排序，默认 100 |
| status | nvarchar(20) | Active / Inactive |
| remark | nvarchar(256) | 可空 |
| + EntityBase 审计/软删字段 | | |

索引：`UX_hr_province_code`（`province_code` WHERE `IsDelete=0`）；`IX_hr_province_status`。

### 4.2 `hr_city` 市

| 列 | 类型 | 说明 |
|----|------|------|
| Id | bigint PK | 雪花 |
| province_code | nvarchar(12) | 所属省代码 |
| city_code | nvarchar(12) | 市代码，未删唯一（全局唯一，便于员工只存市码也能反查） |
| city_name | nvarchar(50) | 市名称 |
| order_no | int | 排序 |
| status | nvarchar(20) | Active / Inactive |
| remark | nvarchar(256) | 可空 |
| + EntityBase | | |

索引：`UX_hr_city_code`；`IX_hr_city_province`；`IX_hr_city_status`。

实体建议：`HrProvince` / `HrCity`（`[SugarTable("hr_province")]` / `hr_city`）。

## 5. 接口（后端）

对齐 `HrPostService` 风格，权限前缀 `hrProvince/*`、`hrCity/*`。

**省**

- `Page` / `Get` / `Save` / `Delete`
- `ListEnabled`：现用省，按 `order_no`、`province_code`

**市**

- `Page`（必带或可选 `ProvinceCode` 过滤）
- `Get` / `Save` / `Delete`
- `ListByProvince(provinceCode)`：该省下现用市

分页入参继承 `BasePageInput`，查询链末端 `.OrderBuilder(input)`。

校验：代码格式与唯一；市的 `province_code` 必须对应未删省；保存时 Trim。

## 6. 前端

路径建议：`Web/src/views/hrms/province/index.vue`（或 `regionCode`），API：`Web/src/api/hrms/hrProvince.ts` + `hrCity.ts`。

**布局（建造方默认）：** 左右分栏  

- 左：省列表（查询关键字、状态；新增/编辑/删；点选当前省）  
- 右：当前省下的市列表（同样 CRUD）  

列：代码、名称、排序、状态、操作；可排序列开 `sortable`；`useVxeTable` + `Local` 记忆排序分页。

不接员工表单。

## 8. 初始化数据

- 幂等种子 SQL：`doc/sql/{当天}/` 下，如 `0x-省市初始化.sql`
- 范围：  
  - 34 个省级（含港澳台）  
  - 各地级市；直辖市各 1 条同名市节点  
  - 港澳：省级 + 同名市（或香港/澳门各一市节点）  
  - 台湾：省级 + 常用地级市清单（种子内固定一版即可，备注来源日期）
- 状态默认 `Active`；`order_no` 按惯用地理/代码序
- **不**从 `SysRegion` 拷贝区县
