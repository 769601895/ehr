# 员工资料导入设计方案

> 会话确认稿。实现前须产品确认本文；确认后再出实施计划。

## 1. 意图与背景

在「人员资料管理」同级新增**员工资料导入**模块，支持按可配置字段模板批量**新增**与**修改**人员主档，并保留导入操作历史。

不塞进「人员资料管理」列表页的原因（已确认）：后续将接入人事**字段权限**，导入的可选列、可写列与列表「编辑」权限模型不同，独立模块更易挂权限与历史，也避免列表页过重。

现有能力对照：

| 现状 | 说明 |
|------|------|
| `Web/src/views/hrms/emp` + `HrEmpService` | 单条新增/编辑人员主档；导入应复用其校验与写库路径（或抽公共写服务），禁止另写一套落库逻辑 |
| `HrUiFieldDef` / `HrUiLayout` FieldPool | 已有人员字段元数据与场景字段池（`moduleCode=hrEmp`），导入可选字段**以字段池为源** |
| `HrEmpIdGenerator` + 公司参数解析 | 工号按部门→归属公司→`HrCompanyParam` 规则发号；导入必须遵守 |
| 人事字段权限 | **新框架尚未落地**（老系统有 `sys_user_column`）；本期仅预留挂点，二期再裁剪可选/可写字段 |
| Excel 导入基础设施 | 人事侧暂无现成「员工导入」页面；实现时可复用平台已有 Excel 读写工具（若有），无则按项目惯例新增 |

## 2. 目标 / 非目标

### 目标

- 菜单与「人员资料管理」**同级**（同属人事资料类父菜单下），标题建议：**员工资料导入**
- 页面作业类型显式二选一：**新增** / **修改**（不做按工号自动判断）
- **个人私有**导入模板：新增模板、修改模板分两类各自配置；支持新建、改字段、删除；下次可复用
- 字段动态配置：从 `hrEmp` 字段池勾选列及顺序；按模板下载 Excel、上传解析
- 整批事务：**任一行失败则整批退回**，并返回/可下载失败原因清单
- 修改时空单元格 = **不修改**该字段；仅非空单元格覆盖
- 新增：工号有填用工号（唯一且不可复用）；留空则按该行部门解析归属公司后自动发号
- 修改模板**强制包含工号**且不可从模板删除；新增模板工号可选
- 导入历史：批次、作业类型、操作人、时间、行数统计、成功/失败、失败明细
- UI 多语言（界面五语）；菜单/权限种子齐全
- 历史列表支持服务端排序（`OrderBuilder`）
- **字段权限二期**：本期字段池全量可选（受模板类型锁定规则约束）；代码预留「按当前用户过滤可导入字段」接口，二期接入后无需改主流程

### 非目标（本期不做）

- 人事字段权限本体（配置页、按角色/用户裁剪读写）
- 模板共享 / 按部门或角色下发
- 部分成功写入（成功行落库、失败行跳过）
- 异步大文件队列（若单批行数过大可二期加；本期同步事务，行数上限由实现约定）
- 子表（家庭、教育、工作经历等）批量导入
- 离职办理、异动单批量导入
- 与钉钉/外部花名册同步

### 反目标（做成了也算失败）

- 在列表页塞一个导入按钮却无独立权限边界，导致二期字段权限无法挂
- 导入绕过工号规则 / 公司参数解析 / 工号不可复用
- 修改时空单元格把字段清空
- 新增与修改混在同一模板且无作业类型，导致误更新/误建档
- 字段权限未做却假装已裁剪（静默丢列）
- 通过导入直接改 `EmpState` 绕过离职/状态流程

## 3. 业务规则

### 3.1 模块与权限

1. 独立菜单 + 独立 API 权限码（如 `hrEmpImport/*`）；与 `hrEmp` 的增删改查权限分离。
2. 管辖部门：导入涉及的部门须在操作人管辖范围内（与人员资料一致的管辖语义）；越权部门整批失败。
3. 字段权限二期：在「取可选字段池」处调用预留过滤器；本期过滤器恒等（全量返回）。

### 3.2 作业类型

| 类型 | 行为 |
|------|------|
| 新增 | 每一行建新人；工号已存在 → 失败；工号空 → 按部门发号 |
| 修改 | 每一行按**工号**定位已有人员；工号不存在 → 失败；空单元格跳过不改 |

页面必须先选类型，再选该类型下的个人模板。

### 3.3 模板

1. 归属：`CreateUserId` = 当前用户；列表/改/删仅本人。
2. 类型：`Add` / `Update` 两套，不可混用。
3. 内容：有序 `fieldKey` 列表；标签下载时取字段池当前文化 Label（主语言列名可与多语表头策略由实现约定，建议表头用当前界面语言）。
4. 修改模板：保存时校验必须含 `empId`（或字段池中工号对应 `fieldKey`）；UI 锁定不可移除。
5. 新增模板：可不含工号；若含，则行内可空（空则发号）。
6. 删除模板：软删；不影响历史批次已记录的模板快照（见历史）。

### 3.4 下载与上传

1. 下载：按模板字段生成标准 **Office Open XML `.xlsx`**（空数据行或带一行示例，**实现约定**：默认仅表头 + 说明行）。兼容微软 Excel 与 WPS 表格；不依赖本机安装微软 Office。
2. 上传：仅接受 `.xlsx`（拒绝 `.xls` / WPS 专有格式）。表头须与当前模板字段一致（列顺序与模板一致；**多余列拒绝，缺列拒绝**）。约定单 Sheet、表头行无合并单元格；合并表头或非标准另存导致的解析失败，提示用户「请另存为 Excel 工作簿 (.xlsx)」。
3. Lookup 列以纯文本填写（码或名），不强依赖 Excel/WPS 数据验证下拉。
4. 预览：服务端校验全部行，返回行级错误；有任一错误不可提交。
5. 提交：再次全量校验 + 单事务写入；**每次提交都落一条历史，状态 Success/Failed**。

### 3.5 工号

遵循项目规则 `emp-id-assign` / `company-param-resolve`：

- 部门 → 向上归属公司 `SiteCode` → `HrCompanyParam` 工号模式。
- 手填冲突、已用（含离职/历史）→ 失败。
- 自动发号在保存事务内占号，防并发撞号；预览不占号。

### 3.6 修改空值语义

Excel 单元格 trim 后为空 → 该字段不更新。  
（若业务将来需要「显式清空」，须另约定特殊占位符；本期不做。）

### 3.7 校验（摘要）

- 必填：以字段池 `Required` + 作业类型规则为准（新增时姓名、部门等；修改时工号必填且每行非空）。
- 码表/lookup（部门、岗位、人员类别等）：单元格**业务码与显示名两者都认**；解析成功后一律落业务码。同名多码歧义 → 该行失败（须填码消歧）。大小写/前后空格 trim 后匹配；显示名按当前可解析数据源（含多语显示名时优先当前文化，回退主名——实现细化）。
- 日期、长度、唯一约束等同单条保存。
- 同一批次内工号重复（新增多行同号，或修改多行同号）→ 失败。

### 3.8 禁止导入的字段

- **人员状态类字段不允许进入导入列**（含在职/停职/离职等 `EmpState` 及同等语义字段）。字段池对导入场景直接剔除；模板保存与 Preview/Commit 双重校验，防止绕过。
- 离职/停职等状态变更不走本模块（与「本期不做离职办理」一致）；新增人员落库状态取单条新增的默认值（通常在职），不由 Excel 指定。

## 4. 页面结构（建议）

单页多 Tab 或左右分区均可，建议：

1. **导入**：选类型 → 选模板 → 下载模板 → 上传 → 预览结果 → 确认导入  
2. **我的模板**：按类型筛选；新建/编辑（字段多选排序）/删除  
3. **导入历史**：分页列表 + 详情/失败明细下载  

（具体布局留给前端实现；须满足多语言与列表排序规则。）

## 5. 数据模型（建议）

库：HR 库（`ApplicationConst.HrDbConfigId`）。表名实现时可微调，语义如下。

### 5.1 `hr_emp_import_tpl` 导入模板

| 列 | 说明 |
|----|------|
| Id | 雪花 PK |
| OwnerUserId | 所属用户 |
| ImportMode | Add / Update |
| Name | 模板名称 |
| Remark | 可空 |
| + EntityBase | 审计/软删 |

索引：`(OwnerUserId, ImportMode, IsDelete)`。

### 5.2 `hr_emp_import_tpl_field` 模板字段

| 列 | 说明 |
|----|------|
| Id | 雪花 PK |
| TplId | 模板 Id |
| FieldKey | 对应 `hr_ui_field_def.field_key` |
| SortNo | 顺序 |
| IsLocked | 是否锁定（修改模板的工号为 true） |

唯一：`(TplId, FieldKey)`。

### 5.3 `hr_emp_import_batch` 导入批次历史

| 列 | 说明 |
|----|------|
| Id | 雪花 PK |
| BatchNo | 业务批次号（可读） |
| ImportMode | Add / Update |
| TplId | 可空（模板已删时仍保留快照） |
| TplNameSnapshot | 模板名快照 |
| FieldKeysSnapshot | JSON 字段列表快照 |
| FileName | 上传文件名 |
| TotalCount / SuccessCount / FailCount | 计数 |
| Status | Success / Failed |
| ErrorSummary | 摘要 |
| OperatorUserId | 操作人 |
| + EntityBase | |

### 5.4 `hr_emp_import_batch_row` 行结果（可选但推荐）

失败行存 `RowNo`、`EmpId`、`ErrorMessage`；成功批次可只存汇总不落行，或抽样——**实现约定：失败时落全部失败行；成功可不落行明细**。

## 6. API 轮廓（建议）

| 能力 | 说明 |
|------|------|
| FieldPoolForImport | 取可导入字段（内部调用字段池 + **预留** `IHrEmpImportFieldFilter`） |
| Tpl Page/Get/Save/Delete | 个人模板 CRUD；Save 校验锁定字段 |
| DownloadTemplate | 按 TplId 生成 xlsx |
| Preview | 上传+校验，不写库、不占号 |
| Commit | 校验+事务写入+记历史 |
| Batch Page/Detail/FailRows | 历史查询（仅本人；是否管理员看全部留给实现默认「仅本人」） |

权限：查询、模板维护、预览、提交、历史 分权（至少「提交」与「模板维护」可分）。

## 7. 字段权限预留（二期）

```text
IHrEmpImportFieldFilter.FilterAsync(userId, mode, poolItems) → poolItems'
```

- 本期默认实现：原样返回。  
- 二期：按用户字段读/写权限过滤；无写权限的字段不可入模板、不可作为导入列。  
- Preview/Commit 亦须再校验，防止篡改模板绕过。

## 8. 多语言

- 页面文案：`Web/src/i18n/pages/hrms/` 下导入模块词条；菜单 `Web/src/i18n/menu` + 后端菜单资源按需。  
- 业务内容：人员姓名等仍走主档；模板名称个人自用，**不做** `*_lang` 译文表（例外：个人私有名称）。  
- Excel 表头：跟当前 UI 文化从字段池取 Label。

## 9. 约束与实现约定（Builder 可定）

以下会话未钉死，实现计划中由 Builder 选定并写明：

- 单批最大行数（建议 500～2000）与文件大小上限  
- Excel 说明行/下拉码表是否写入模板  
- 历史是否仅本人可见  
- 与 `HrEmpService.Save` 复用方式（直接调 vs 抽 `HrEmpWriter`）  
- 精确菜单父级 Id、权限码字符串、表名前缀最终名  

## 10. 验收要点

- [ ] 同级菜单「员工资料导入」；权限与人员资料分离  
- [ ] 新增/修改分模板；个人私有；修改模板工号锁定  
- [ ] 动态选字段 → 下载 → 上传 → 预览 → 整批提交或整批退回  
- [ ] 修改空单元格不改；新增工号可空发号/可填校验  
- [ ] 导入历史可查；失败可看行因  
- [ ] 工号与公司参数规则正确；管辖越权失败  
- [ ] UI 多语言；历史列表可排序  
- [ ] 存在字段过滤预留点，本期不过滤  

## 11. 已确认决策一览

| 项 | 结论 |
|----|------|
| 模块形态 | 新建同级模块，非列表页内嵌 |
| 新增+修改 | 都要；页面显式选择类型 |
| 失败策略 | 整批退回 |
| 历史 | 要 |
| 模板 | 个人私有；每账号仅「新增」「修改」各一份，无模板名称维护 |
| 字段 | 动态配置；按作业类型调整对应模板字段即可 |
| 工号 | 有填用填；空则自动发号（新增） |
| 修改空单元格 | 不修改 |
| 字段权限 | 导入先上；接口预留二期 |
| Lookup 单元格 | 业务码与显示名都认，落库用码；歧义失败 |
| EmpState 等状态字段 | 不允许导入 |
