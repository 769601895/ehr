# 05-动态字段赋值规则引擎方案（通用）

日期：2026-10-31  
定位：公司参数 / 入职 / 异动等场景下，**多数字段的动态默认与派生赋值**统一配置，而不仅是工号。  
工号拼装是本引擎的一种算子；详见 [04-工号规则可配置生成方案.md](./04-工号规则可配置生成方案.md)。  
原型：[原型-动态字段赋值规则.html](./原型-动态字段赋值规则.html)

---

## 1. 为什么要通用化

公司参数里大量是「策略旋钮」，真正落在员工主数据上时是**按规则算出来的值**，例如：

| 场景 | 目标字段 | 典型规则 |
|------|----------|----------|
| 入职 | 工号 `emp_id` | 段拼装 + 号段占用 |
| 入职 | 试用到期日 `emp_try_date` | 入职日 + 试用期限（月/天）±「当天是否有效」 |
| 入职 | IC 卡号 | 与工号一致 / 手工 / 其他映射 |
| 入职 | 考勤方式 | 取公司参数默认值 |
| 异动 | 新试用到期日 | 异动生效日 + 异动试用期限（若启用） |
| 其他 | 合同到期、下次体检等 | 基准日 + 周期 |

若每种都在后端 `if/else` 写死，参数页再多下拉也只是「存数」；**规则本身不可见、不可扩展**。  
通用方案：前端配置「何时、给谁、怎么算」；后端统一解释执行。

---

## 2. 原则

1. **配置可见**：规则在 UI 上可读、可预览（样例入职日 → 样例试用到期日 / 样例工号）。  
2. **执行在后端**：保存员工时服务端求值；前端预览不落库（工号预览不占号）。  
3. **算子封闭、组合开放**：只开放有限算子（日期偏移、段拼装、取参数、复制字段、常量、码表默认），禁止任意脚本。  
4. **绑定触发点**：规则挂在业务事件上（`OnHireSave` / `OnEmpChgSave`…），不是全局魔法字段。  
5. **公司参数仍是旋钮**：期限天数、是否含当天、默认考勤方式等继续进 `HrCompanyParam`；引擎**引用**这些旋钮，而不是取代参数表。

---

## 3. 概念模型

```text
规则集 RuleSet（按厂别 + 业务事件）
  └─ 规则 Rule（有序；可停用）
        ├─ 目标字段 targetField（元数据字段名 / 列名）
        ├─ 条件 when（可选：仅新进试用=是 才算试用到期）
        ├─ 算子 kind + 参数
        └─ 覆盖策略：仅空时填 / 总是覆盖 / 仅新增
```

### 3.1 业务事件（trigger）

| trigger | 时机 |
|---------|------|
| `hire.create` | 新进保存前赋默认 |
| `hire.update` | 编辑在职（可选，默认多数规则不跑） |
| `empChg.apply` | 异动生效 |
| `manual.preview` | 仅预览 |

### 3.2 算子 kind（第一期建议）

| kind | 用途 | 参数要点 |
|------|------|----------|
| `compose` | 工号等字符串拼装 | 段列表（同 04 文档） |
| `dateOffset` | 试用到期等 | `baseField`、`offsetFrom`（参数或常量）、`unit`（day/month）、`inclusive`（参数引用） |
| `copyField` | IC=工号 | `sourceField` |
| `fromParam` | 考勤方式默认 | `paramKey`（公司参数属性名） |
| `constant` | 固定默认 | `value` |
| `manual` | 不自动赋 | — |

`dateOffset` 示例（试用到期日）：

```json
{
  "kind": "dateOffset",
  "targetField": "emp_try_date",
  "baseField": "emp_in_date",
  "offsetFrom": { "param": "ProbationHireDays" },
  "unit": "month",
  "inclusiveFrom": { "param": "ProbationDayInclusive" },
  "when": { "paramEquals": ["ProbationOnHire", 1] }
}
```

语义需在 SPEC 中写死一种（建议）：

- `inclusive=是`：到期日 = 入职日 + N 月 − 1 天（含入职日当天算满期常见算法，以实现时与法务/旧系统对齐为准）。  
- 或：到期日 = 入职日 + N 月，再按「当天是否有效」微调。  
**实现前用旧系统样例日对拍一条黄金用例。**

## 4. 与公司参数、字段元数据的关系

```text
HrCompanyParam          —— 厂别旋钮（期限、模式码、默认值）
HrFieldMeta / 字段池    —— 目标字段合法集、控件类型
HrAssignRule(+Seg)      —— 动态赋值规则（本方案）
业务 Service            —— 触发 Evaluate(trigger, context)
```

- 参数页：继续维护旋钮；可增加入口「查看本厂入职赋值规则」。  
- 规则页：选目标字段、选算子、引用参数；预览用模拟上下文。  
- 人员新增：Service 调引擎 → 填 DTO 空字段 → 再校验保存。

## 5. 数据与 API（草案）

### 5.1 表

`HrAssignRuleSet`：`SiteCode`, `Trigger`, `Name`, `Enabled`  
`HrAssignRule`：`SetId`, `OrderNo`, `TargetField`, `Kind`, `ConfigJson`, `WhenJson`, `FillMode`, `Enabled`  
工号号段仍用 `HrEmpIdSeq`（仅 `compose`+seq 使用）。

快速版：单表 `HrAssignRule` 含 `SiteCode+Trigger`，`ConfigJson` 内嵌段。

### 5.2 API

| API | 说明 |
|-----|------|
| 规则 CRUD / 按厂别+trigger 列表 | 配置端 |
| `POST .../assignRule/preview` | 入参：规则快照 + 模拟员工上下文 → 各目标字段样例值 |
| 内部 `AssignRuleEngine.ApplyAsync(trigger, site, entity)` | 业务调用 |

---

## 6. 前端形态

1. **规则列表**：按「入职默认 / 异动」页签。  
2. **一行一条字段规则**：目标字段、算子、摘要、启用。  
3. **编辑抽屉**：  
   - `dateOffset`：选基准字段、偏移来源（参数下拉）、单位、含首日策略。  
   - `compose`：复用工号段编辑器（04 原型）。  
4. **预览区**：模拟入职日、试用否等 → 算出试用到期日、工号等。

配置过程对业务可见；不是藏在后端代码注释里。

---

## 7. 分期

| 阶段 | 内容 |
|------|------|
| P0 | 模型 + 配置 UI + Preview；先接 `dateOffset`（试用到期）与 `fromParam`（考勤默认） |
| P1 | `compose` + 号段；入职保存调用引擎 |
| P2 | 异动触发、条件 when、审计、与字段元数据强校验 |

**04 工号方案**作为 `compose` 算子的专项说明，不再单独做成第二套互不相干的配置体系。

---

## 8. 风险

- 日期算法与旧 HR 不一致 → 必须对拍用例。  
- 规则顺序：先 `compose` 工号，再 `copyField` IC，顺序可配置。  
- 过度配置：默认只开放「入职」若干字段；高级算子权限控制。

---

## 9. 结论

工号生成、试用到期日、以及后续更多「由参数/基准字段派生」的赋值，应落在同一套 **动态字段赋值规则引擎** 上：  
**公司参数提供旋钮，规则引擎描述赋值过程，业务事件触发执行。**  
这样前端能看到、能改过程；后端只维护有限算子，避免每个字段一套硬编码。
