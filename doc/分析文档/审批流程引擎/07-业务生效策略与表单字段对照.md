# 业务生效策略与表单字段对照

> 分析日期：2026-10-29  
> 状态：P0 文档/SQL 已落库；P1 代码已实现（Handler/Apply/Job），待联调  
> 关联：`IHrWfBizHandler`、异动到日写回、离职次日生效

## 1. 目标与原则

| 目标 | 说明 |
|------|------|
| 审核通过 ≠ 主档生效 | 通过只到「待生效」；写主档走统一 Apply |
| 生效时机可配置 | 异动：异动日**当日**；离职：离职日**次日** |
| 写回字段可配置 | 表单 fieldKey ↔ 主档列；区分 Subject / Before / After |
| 引擎不写主档 | `Approve` 只回调 Handler；Handler 调 Apply 或挂起待 Job |

**非目标（本期）：** 分钟级生效、万能动态 SQL 写任意表、在 `Approve` 内写死 BizType 分支改 `h_emp_mstr`。

## 2. 两配置配合

```text
FormData / 业务单
        │
        ├─► hr_wf_effect_policy     → 计划生效日 = 基准日 + day_offset
        │
        └─► hr_wf_effect_field_map  → Subject / Before / After / EffectBaseDate
                        │
                        ▼
              待生效 ∧ 已到期 → EffectApply → 主档（白名单列）
```

| 配置表 | 回答 |
|--------|------|
| `hr_wf_effect_policy` | **哪天**可以写主档 |
| `hr_wf_effect_field_map` | Form **哪个键**对应主档 **哪一列** |

按 `biz_type` 启用；二者齐全才能做通用写回。

## 3. 状态与时机

```text
Running ──通过──► Approved(待生效) ──到计划生效日──► Effective(已写主档)
              └──驳回──► Rejected（不写主档）
Effective ──撤销──► Voided（按 Before 回滚，业务模块）
```

```text
plan_effect_date = Date(基准日) + day_offset
可 Apply ⇔ 待生效 ∧ plan_effect_date ≤ 业务今天
```

「业务今天」一期用服务器本地日期；后续可接人事日切点。

## 4. 表设计

### 4.3 `role` 语义

| role | 用途 |
|------|------|
| Subject | 定位主体（工号 → 员工） |
| EffectBaseDate | 生效基准日 |
| After | **正向写回**主档 |
| Before | 快照 / **撤销回滚**；正向 Apply 不用 |
| Context | 仅展示上下文，不写主档 |

### 4.4 可选 `hr_wf_effect_pending`（纯表单 B、无业务明细时）

| 列 | 说明 |
|----|------|
| biz_type, biz_id | 多为 wf instId |
| emp_id | Subject |
| plan_effect_date | |
| status | Pending / Applied / Cancelled |
| payload_json | 冻结的 Before/After |
| applied_time | |

有 `hr_emp_chg` / `_line` 时 Apply **优先读业务明细**，可不建 pending。

### 4.5 幂等日志（建议）

`hr_wf_effect_log`：biz_type、biz_id、action（Apply/Void）、success、message、time。  
或复用异动 `hr_emp_chg_apply_log`。

## 5. 种子数据

### 5.1 策略

| biz_type | base_date_field | day_offset | apply_mode | 说明 |
|----------|-----------------|------------|------------|------|
| hrEmh | emh_date | 0 | ImmediateIfDue | 异动日当日（表单暂无日期字段时见 §5.3） |
| hrEmpLeave | leave_date | 1 | ImmediateIfDue | 离职日次日 |

### 5.2 异动 `hrEmh` 字段对照（与当前审批表单对齐）

| form_field_key | role | db_column | pair_group |
|----------------|------|-----------|------------|
| emp_id | Subject | | |
| emh_date | EffectBaseDate | | |
| emp_name | Context | | |
| emh_occ | Before | cc_code | dept |
| emh_ncc | After | cc_code | dept |
| opost_id | Before | post_id | post |
| npost_id | After | post_id | post |

### 5.3 基准日过渡

若启用中的 `hrEmh` 表单尚无 `emh_date`：

1. **推荐**：表单方案增加日期字段 `emh_date`（异动日期），与 map/policy 对齐；或  
2. 过渡：`base_date_source=Biz` + 业务单 `chg_date`；纯 B 无业务单时可用「通过日」仅作联调，**不作为正式规则**。

SQL 种子见：`doc/sql/2026-10-29/10-业务生效策略与字段对照.sql`。

## 6. 运行时

### 6.1 `OnApproved`（Handler）

1. 读 policy（无则只落流程终态，不写主档）。  
2. 读 field_map：解析 Subject、EffectBaseDate、Before/After。  
3. 算 `plan_effect_date`；业务单或 pending → 待生效。  
4. `ImmediateIfDue` 且已到期 → `TryApply`；否则等 Job。

### 6.2 `TryApply`（唯一写主档入口）

1. 校验待生效、已到期、幂等。  
2. 数据源优先级：业务明细（`hr_emp_chg_line`）> pending.payload > FormData+map(After)。  
3. 仅写 map/明细允许的 `db_column`。  
4. 置 Effective；写日志。

### 6.3 Job

周期扫描「待生效且 plan_effect_date≤今天」→ `TryApply`。

### 6.4 撤销

仅 Effective；按 Before / `value_before` 回滚；Voided。

## 10. 分期与验收

| 期次 | 内容 |
|------|------|
| P0（本文档 + SQL） | ✅ 两表 DDL、pending、hrEmh/离职策略与对照种子；表单补 `emh_date` |
| P1 | ✅ `HrWfEffectApplyService`、`HrEmhWfBizHandler`、`HrWfEffectApplyJob`、策略只读 API；异动部门/岗位白名单写回 |
| P2 | ✅ 维护页「业务生效策略」（流程配置旁）；Save/Void API；`HrEmpLeaveWfBizHandler`；生效写 `h_emh_hist`；撤销回滚主档 |

验收：

- [ ] 异动：After 写部门/岗位；Before 仅撤销用  
- [ ] 无 map 或不含 After → 通过不改主档  
- [ ] offset=0：未到异动日主档不变；到期或通过日≥异动日可生效  
- [ ] offset=1：离职日当天通过不生效，次日生效  
- [ ] Job 与即时 Apply 幂等一致  
- [ ] 驳回永不写主档
