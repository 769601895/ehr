# 审核角色树形汇报链 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans，按任务逐步实现。步骤使用 checkbox（`- [ ]`）跟踪。

**Goal:** 将审批角色改为全局汇报树；新开单按当事人岗位建上级路径；流程节点可按**等级 / 个人 / 岗位**+条件派单；在途单保持旧 Level+AuditOrder。

**Architecture:** `HrWfReportPath` 管路径；`HrWfAssigneeResolver` 增加按 RoleId、按 Post 解析；Runtime 快照双轨 + 条件求值 + 全跳过报错；角色树 API/校验；前端角色左树右表 + 定义页三种审批人规则。

**Tech Stack:** Admin.NET / SqlSugar / xUnit；Vue3 + Element Plus + vxe-grid（右表远程排序）。

**Spec:** [`05-审核角色树形汇报链改造方案.md`](./05-审核角色树形汇报链改造方案.md)

## Global Constraints

- 全局一棵树；`ParentId` = 汇报上级；流程节点 `AssigneeRule` = `Level` | `FixedUser` | `Post`，均可配 `ConditionJson`。
- 仅 `Level` 依赖汇报路径；`FixedUser`/`Post` 与路径无关。
- 路径锚点 = **单据当事人** `SubjectEmpId` → `HrEmployee.PostId`；跳过本人节点。
- 路径上同 `LevelId` 不可重复；空人/条件假/Level 不在路径 → 跳过单节点；**全部跳过 → 报错**。
- 在途：`AssigneeResolveMode=LegacyLevel`；新开：`ReportPath`（写入 `DefNodesSnapshot`）。
- 树数据不导入，管理员重建；列表排序遵守 `page-list-sorting`；SQL 入 `doc/sql/{yyyy-MM-dd}/`。
- 提交仅在用户明确要求时执行。

## Review Focus

1. 代提：发起人岗位与当事人不同 → 路径只跟 `SubjectEmpId`。  
2. 在途旧单 Approve → 仍走 `ResolveByLevelAsync` 升级，不读汇报树。  
3. 新开单所有 Level 节点均不在路径 / 条件假 / 无人 → Start 失败，实例不落 `Approved`。  
4. 保存角色造成祖先链等级重复或成环 → Save 拒绝。  
5. 路径角色管辖不覆盖 `SubjectCcCode` → 该节点跳过（计入全跳过判定）。
