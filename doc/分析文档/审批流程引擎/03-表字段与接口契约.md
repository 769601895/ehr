## 1. 约定

| 项 | 约定 |
|----|------|
| 库 | HR 库（与 `HrUiLayout` 相同：`[Tenant(ApplicationConst.HrDbConfigId)]`） |
| 基类 | `EntityBase`（含 `Id` 雪花、审计、软删 `IsDelete` / `DeleteTime`） |
| 表名 | snake_case：`hr_wf_*` |
| C# 属性 | PascalCase；`SugarColumn(ColumnName = "snake")` |
| 列表排序 | 入参 `Field` / `Order` / `DescStr`，后端 `OrderBuilder` |

| JSON | 属性 camelCase（与前端一致） |

## 2. 枚举与常量

### 2.1 表单模式 `FormMode`

| 值 | 含义 |
|----|------|
| `B` | 引擎自定义字段；值在 `FormDataJson`（**默认**） |
| `A` | 池字段 + 可写回（P0 仅预留列；不实现写回） |

### 2.2 控件类型 `ControlType`（P0）

| 值 | 说明 |
|----|------|
| `text` | 单行文本 |
| `textarea` | 多行文本 |
| `number` | 数字 |
| `date` | 日期 |
| `select` | 下拉（需 `CodeField` → 人事代码） |
| `attachment` | 附件（存文件 Id/URL 约定，见 §4.3） |
| `user` | 人员（用户 Id） |
| `dept` | 部门（`CcCode`） |

### 2.3 字段来源 `FieldSource`

| 值 | 含义 |
|----|------|
| `Custom` | 模式 B 自定义（默认） |
| `Pool` | 模式 A 字段池引用（P0 可不使用） |

### 2.4 实例状态 `InstStatus`

| 值 | 含义 |
|----|------|
| `Running` | 审批中 |
| `Approved` | 全部通过（终态） |
| `Rejected` | 已驳回（终态） |
| `Cancelled` | 已撤销（终态；P0 可不暴露撤回 API） |
| `Suspended` | 挂起（预留） |

### 2.5 任务状态 `TaskStatus`

| 值 | 含义 |
|----|------|
| `Pending` | 待处理 |
| `Approved` | 已同意 |
| `Rejected` | 已驳回 |
| `Cancelled` | 已取消（节点推进后同节点其余待办关闭；或签） |
| `Transferred` | 已转交（P1） |

### 2.6 节点多人模式 `NodeMode`（P0）

| 值 | P0 行为 |
|----|---------|
| `Serial` | 节点内按解析出的人派待办；**一岗多人默认按或签**处理（一人同意即关同节点其余 Pending） |
| `And` | 会签（P1 显式；P0 可存值但不作为主路径验收） |
| `Or` | 或签（与多人默认行为一致，可显式标注） |

### 2.7 审批人规则类型 `AssigneeRule.type`

| 值 | 载荷要点 |
|----|----------|
| `Level` | `{ "type":"Level", "levelId": 123 }`（**P0 主路径**） |
| `FixedUser` | `{ "type":"FixedUser", "userIds":[1,2] }` |
| `DeptManager` | `{ "type":"DeptManager" }` |
| `Reporter` | `{ "type":"Reporter" }` |

### 2.8 操作日志 `ActionType`

`Start` / `Approve` / `Reject` / `Escalate` / `SkipEmpty` / `PatchForm` / `Transfer` / `Cancel`（后两者 P1）

## 4. JSON 形状

### 4.1 `AssigneeRuleJson`

```json
{ "type": "Level", "levelId": 10001 }
```

### 4.2 `FormDataJson`

键 = `field_key`；值为 JSON 原生类型或约定对象：

```json
{
  "subject": "办公用品采购",
  "amount": 1200.5,
  "needDate": "2026-11-01",
```

附件建议：`{ "fileIds": [1,2] }` 或项目既有附件结构；P0 可先存字符串 URL 列表。

```json
      "fieldKey": "subject",

      "groupCode": "main",

      "codeField": null
```


## 5. 接口契约

逻辑服务名如下；实现时映射到 `Service/Hr/Wf/*`。分页入参均继承项目 `BasePageInput`（含 `Field`/`Order`/`DescStr`）。

### 5.1 `HrWfLevelService`

| 方法 | 入参 | 出参 | 说明 |
|------|------|------|------|
| `Page` | 关键字、enabled | 分页 | 默认 `auditOrder` asc |
| `Get` | `id` | 详情 | |
| `Save` | code/name/auditOrder/isFunctional/orderNo/enabled/remark | id | 新增或更新 |
| `Delete` | `id` | — | 软删；有角色引用时拒绝或级联策略：**P0 拒绝** |
| `ListEnabled` | — | 下拉列表 | 流程配置用 |

### 5.2 `HrWfRoleService`

| 方法 | 入参 | 出参 | 说明 |
|------|------|------|------|
| `Page` | levelId?、关键字 | 分页 | |
| `Get` | `id` | 角色 + scopes[] + postIds[] | |
| `Save` | levelId、code、name、enabled、**scopes: {ccCode,includeChild}[]**、**postIds: long[]** | id | 整单覆盖 scope/post |
| `Delete` | `id` | — | 软删角色并清 scope/post（或软删） |

### 5.3 `HrWfFormService`

| 方法 | 入参 | 出参 | 说明 |
|------|------|------|------|
| `Page` | bizType?、关键字 | 分页 | |
| `Get` | `id` | form + fields | |
| `GetByBizType` | `bizType` | **启用中** form + fields | 无启用 → 业务错误 |
| `Save` | 头 + fields[]；`formMode` 默认 `B` | id；`version++` | 同 bizType 启用互斥 |
| `Delete` | `id` | — | 已被启用流程引用则拒绝 |

### 5.4 `HrWfDefService`

| 方法 | 入参 | 出参 | 说明 |
|------|------|------|------|
| `Page` | bizType? | 分页 | |
| `Get` | `id` | 头 + nodes | |
| `GetEnabledByBizType` | `bizType` | 启用定义 + nodes | |
| `Save` | 头（含 FormId、编辑三开关、timeout）+ nodes[] | id；`version++` | nodes 整单替换 |
| `Delete` | `id` | — | |

### 5.5 找人 `HrWfAssigneeResolver`（内部服务，可无 HTTP）

| 方法 | 入参 | 出参 |
|------|------|------|
| `ResolveByLevelAsync` | `levelId`, `subjectCcCode`, `escalateIfEmpty=true` | `List<long>` 用户 Id（去重） |

**算法（锁定）：**

1. 取该等级下 `enabled` 角色。  
2. 仅保留 **至少一条 scope 且覆盖** `subjectCcCode` 的角色（`include_child` → 前缀匹配）。  
3. 角色 → posts → 在岗员工（`PostId`）→ `SysUser.JobNum = EmpId`（或项目既定工号字段）。  
4. 若空且允许升级：找下一档 **非职能**、`audit_order` 更大的等级，重复；写 `Escalate` 日志。  
5. 到顶仍空：返回空列表（Runtime 记 `SkipEmpty` 并跳节点）。

### 5.6 `HrWfRuntimeService`

#### `StartAsync`

**入参 `HrWfStartInput`：**

| 字段 | 必填 | 说明 |
|------|------|------|
| `bizType` | Y | |
| `formData` | Y | object / Dictionary |
| `subjectCcCode` | Y | Level 必填 |
| `bizId` | N | 空则用新实例 Id.ToString() |
| `subjectEmpId` | N | |
| `title` | N | 空则从 FormData.subject 或默认文案 |
| `applicantUserId` | N | 空则当前用户 |

**行为：**

1. 加载启用 Def + Form；校验 FormData 必填（按 Schema）。  
2. 同 `bizType+bizId` 已有 `Running` → 错误 `Wf.DuplicateRunning`。  
3. 写 `hr_wf_inst`（快照 Schema + Nodes + 编辑开关拷贝）；`status=Running`。  
4. 按首个启用节点解析审批人并建 `Pending` tasks；无人则升级/跳过直至有人或结束。  
5. 写 `Start` 日志。  
6. 返回 `{ instId, bizId, status, currentNodeKey }`。

#### `ApproveAsync` / `RejectAsync`

| 字段 | Approve | Reject |
|------|---------|--------|
| `taskId` | Y | Y |
| `opinion` | N | **Y** |
| `formDataPatch` | 可选 | 可选 |

**行为：**

- 校验 `task.assigneeId == 当前用户` 且 `Pending`，否则 `Wf.NotAssignee`。  
- 若带 patch：仅当实例开关 + 身份允许，否则 `Wf.FormEditDenied`；允许则合并 FormData + `PatchForm` 日志。  
- **Reject：** task→Rejected；同节点其余 Pending→Cancelled；inst→Rejected；`finished_time`；日志。  
- **Approve（或签）：** task→Approved；同节点其余 Pending→Cancelled；推进下一节点或 Approved 终态。  
- 无 Handler 时**不写**业务主档。

#### `TryPatchFormDataAsync`（可并入详情保存）

独立补丁接口；规则同 §6.5 开关。驳回后非 Running 的再提交策略：P0 **重新 Start**（新实例或新 bizId），不依赖 Running 编辑开关。

#### `GetDetail`

`instId` → 实例 + 快照 Schema + FormData + 任务列表/进度 + 当前用户可操作标记（`canApprove`/`canReject`/`canEditForm`）。

### 5.7 `HrWfTodoService`

### 7.3 端到端验收路径

1. 配置等级/角色/管辖/岗位 → 保存后 Get 回显正确。  
2. 配置 `hrWfGeneral` 表单字段 → `GetByBizType` 返回完整 Schema。  
3. 配置 2 级 Level 流程并启用。  
4. 发起：填表 → Start → 待办人收到 Pending。  
5. 一岗两人：或签一人同意 → 另一人任务 Cancelled → 进入第二级。  
6. 第二级同意 → `Approved`；库中无业务主档写入。  
7. 另单：第一级驳回（必填意见）→ `Rejected`；Running 下改字段被拒。  
8. 改表单字段标签后，旧实例详情仍显示**快照**标签。  
9. 无 scope 角色不出现在跨厂单据审批人中。

- Handler / 模式 A 写回  
- 会签 AND 强制全员  
- 撤回、转交、超时升级、条件跳过  
- 钉钉/企微、管理员干预  
- 独立可视化表单大画布
