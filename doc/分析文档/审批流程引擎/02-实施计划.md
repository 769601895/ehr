# 审批流程引擎 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐步实现。步骤使用 checkbox（`- [ ]`）跟踪。  
> 评审通过前**不写产品代码**；本计划论证依据为方案文档。

**Goal:** 落地全系统共用审批引擎 P0：审核等级找人（含管辖部门）+ 按 BizType 可配置表单（模式 B）+ 通用发起/待办 + Start/Approve/Reject。

**Architecture:** 在 `Admin.NET.Application` 新建 `hr_wf_*` 实体与 `Service/Hr/Wf/` 运行时；前端 `Web/src/views/hrms/wf/` 提供配置页与通用表单页。流程与表单定义开单时快照；找人链路为等级 → 管辖覆盖角色 → 岗位 → `HrEmployee.emp_id` ↔ `SysUser.JobNum`。试点 BizType：`hrWfGeneral`（纯 B，无业务 Handler）。

**Tech Stack:** Admin.NET / SqlSugar / Furion；Vue3 + Element Plus + vxe-grid（列表远程排序）；组织部门内码 `CcCode`（对齐管辖部门前缀匹配语义）。

**Spec:** [`01-方案设计.md`](./01-方案设计.md)；字段与 API：[`03-表字段与接口契约.md`](./03-表字段与接口契约.md)

## Global Constraints

- 表前缀固定 `hr_wf_*`；审批角色**不与** `SysRole` / `SysUserRole` 关联。
- 新业务默认表单模式 **B**（`FormDataJson`）；`AllowEditWhileRunning` **默认关**。
- `Level` 找人必须结合管辖部门与单据 `SubjectCcCode`；角色无管辖配置则跳过。
- 一岗多人：多人待办，**默认或签**。
- 列表/分页页必须服务端排序：入参 `field` / `order` / `descStr`，后端 `OrderBuilder`（见仓库 `page-list-sorting` 规则）。
- 新建 SQL 放入 `doc/sql/{yyyy-MM-dd}/`；本目录分析文档中文命名。
- 引擎无 Handler 时**不写**业务主档；异动模式 A / Handler 不在 P0。

## Review Focus

1. 角色未配管辖部门 → 解析结果不含该角色任何人。  
2. 跨厂同等级 → 仅管辖覆盖 `SubjectCcCode` 的角色被命中。  
3. 改流程/表单定义后 → 已启动实例仍用快照，审核人与 Schema 不「突然变」。  
4. 非当前任务 `AssigneeId` → Approve/Reject 被拒绝。  
5. 纯 B 试点无 Handler → 终态只更新 `hr_wf_inst`，不写 `h_emp_mstr` 等主档。

（对应验证见 Task 3、Task 6、Task 9。）
