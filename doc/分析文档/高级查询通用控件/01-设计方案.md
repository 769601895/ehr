# 高级查询通用控件 — 设计方案

## 1. 目标

各业务列表复用的「高级查询」能力：

- 行式条件：字段 + 运算符 + 值
- 行/组间连接：并且 / 或者
- 括号分组（嵌套条件组）
- 保存方案：个人可见；可分享给同角色
- 可查字段由**业务页/模块元数据注入**；自定义表单字段变化时，已存方案打开标失效，须改后才能查询
- 跨表字段：以对应页面可查注册为准，不臆造 Join

## 2. 复用已有能力

Admin.NET 已有：

- `BaseFilter.Filter` / `Filter` 树（`Logic` + `Filters` + `Field`/`Operator`/`Value`）
- `ISugarQueryable.AdvancedFilter(Filter)` 表达式应用

本方案在其上补：

1. **白名单消毒**（仅允许模块注册字段 → 实体属性/已声明跨表处理器）
2. **组节点判定修正**（有子 `Filters` 视为组；勿依赖 `Enum.IsDefined(Logic)`）
3. **方案持久化与同角色分享**
4. **前端通用抽屉控件**（字段配置入参 + 失效校验）

## 3. 前端控件契约

```ts
// 业务页传入
fields: AdvQueryField[]
moduleCode: string   // 如 hrEmp，用于方案隔离

interface AdvQueryField {
  field: string;           // fieldKey，如 empId
  label: string;
  valueType: 'string'|'number'|'date'|'datetime'|'enum'|'boolean';
  operators?: string[];    // 默认按 valueType
  options?: { label: string; value: string|number }[];
  origin?: 'physical'|'computed'|'lookup'|'join';
  stale?: boolean;         // 打开方案时由控件回写
}

// 条件树（与后端 Filter JSON 对齐，field 用 camelCase fieldKey）
interface AdvFilterNode {
  logic?: 'And'|'Or';
  filters?: AdvFilterNode[];
  field?: string;
  operator?: 'EQ'|'NEQ'|'LT'|'LTE'|'GT'|'GTE'|'Contains'|'StartsWith'|'EndsWith';
  value?: unknown;
}
```

交互：抽屉；添加条件 / 添加组；方案下拉（我的 + 同角色分享）；保存/另存/分享角色多选；查询前若有失效条件则拦截并高亮。

## 4. 字段变化策略

| 场景 | 行为 |
|------|------|
| 打开方案，fieldKey 不在当前 `fields` | 该节点 `stale=true`，红框提示 |
| 点查询仍有 stale | 拦截，提示先改或删除失效条件 |
| 列表布局/字段池变更 | 下次打开高级查询用最新 `fields`，不影响未打开的方案存储 |

人员资料：`fields` 由列表布局/字段池动态生成（physical + 页面注册的 join，如部门名）；`computed`（如 age）默认不入可筛，除非页面显式注册转换规则。

## 5. 后端

### 5.1 查询

`HrEmpPageInput` 已继承 `BasePageInput` → `Filter`。`BuildQuery` 末尾：

`q = HrAdvancedFilter.Apply(q, input.Filter, hrEmpFieldRegistry);`

注册表：`fieldKey` → 属性名或跨表处理器；未登记字段丢弃/报错（统一报「存在非法或已失效筛选项」）。

### 5.2 方案表 `hr_adv_query_scheme`

| 列 | 说明 |
|----|------|
| ModuleCode | 模块码 |
| Name | 方案名 |
| FilterJson | 条件树 JSON |
| OwnerUserId | 所有者 |
| IsShared | 是否分享 |
| ShareRoleIds | 分享角色 Id 列表（JSON 数组）；同角色可见 |

可见性：`OwnerUserId = 当前用户` **或**（`IsShared` 且 `ShareRoleIds ∩ 当前用户 RoleIds` 非空）。

### 5.3 API（`hrAdvQueryScheme`）

- `list?moduleCode=`
- `save` / `update` / `delete`
- `detail`

权限挂人员资料按钮下，后续其它模块复用同一 API，仅 `moduleCode` 不同。

## 6. 跨表 / 代码类（人员资料）

存**编码**、界面显示**名称**的字段，条件值可按名称或编码筛（避免「包含经理」对 `post_id` 码查空）：

| fieldKey | 处理 |
|----------|------|
| 主表纯文本/日期等 | 实体属性直筛 |
| `ccDesc` | `cc_mstr` 部门名称 |
| `postId` | `hr_post` 岗位名称/编码 |
| `empProvince` / `empCity` | `hr_province` / `hr_city` 名称/编码 |
| `empSex` `empRgt` `empCountry` `empMarry` `empType` `empSal` `empChar1`… | `code_mstr` 描述/码值 |
| `empState` | 在职/停职/离职 或 1/2/3 |
| `age` 等 computed | 不入可筛 |

其它业务页：在该页 `FieldRegistry` 登记同样规则即可。

## 7. 多语言

控件文案进 `Web/src/i18n/pages/hrms`（或 `common` 组件词条）；方案名称用户自填，不做业务译文表。

## 8. 非目标

- 任意 SQL / 未注册跨模块 Join
- 方案跨租户、审批
- 超过 3 层分组（UI 限制，防滥用）
