# 业务界面配置中心 — 详细开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 `HrUi*` 元数据上建成「业务界面配置中心」，支持按模块配置 list/form 显示与交互，并用第二业务模块打通运行时消费样板。

**Architecture:** 扩展 `HrUiModuleCatalog` 登记多模块；配置中心壳按模块切换并复用 `layoutEditor`；字段池 + 系统默认布局种子；业务页经 `GetEffective` 驱动列/表单。不另起设计器、不做 EAV、不把权限/流程塞进布局。

**Tech Stack:** Admin.NET + SqlSugar；Vue3 + Element Plus + vxe-grid；已有 `hr_ui_field_def` / `hr_ui_layout*`；vue-i18n + `HrUiCulture`。

**Spec:** [01-可行性与方案.md](./01-可行性与方案.md)；前置 [../通用表单设计/01-通用表单设计.md](../通用表单设计/01-通用表单设计.md)。

## Global Constraints

- 范围仅 **L1 显示 + L2 交互形态**；L3 功能开关不进布局表。
- 布局字段必须落在模块字段池内；无实体/`FieldKey` 不可配。
- 服务端校验为权威；布局 `required` 只加强前端提示。
- 新列表遵守：`page-list-sorting`、`adv-query-required`、`i18n-multilang-required`；列表组织树遵守 `list-org-tree-panel`。
- SQL 新稿进 `doc/sql/{yyyy-MM-dd}/`；分析文档中文命名。
- 方案权限继续复用 `hrUiLayout/*`、`hrAdvQueryScheme/*`，勿为配置中心乱占历史菜单 Id。

## Review Focus

1. Catalog 未登记模块仍被拒绝（防越权配幽灵模块）。
2. 切换模块后设计器不串 `hrEmp` 硬编码数据。
3. 锁定字段（如主键类）保存时被强制保留。
4. 第二模块列表列与高级查询字段同源字段池，无第三份硬编码。
5. 配置中心与「表单内部门选择弹窗」「列表组织树面板」职责不混用。

## Task 2 — layoutEditor 去硬编码（前端，1d）

**Goal:** 同一设计器服务任意已登记 `moduleCode`，不再写死 `hrEmp` / `h_emp_mstr`。

参考现状：`layoutEditor.vue` 内 `getHrUiFieldPool('hrEmp')`、`saveDefault({ moduleCode: 'hrEmp' })`、表名列写死 `h_emp_mstr`。

- [x] **Step 1:** Props 增加必填 `moduleCode: string`；保留 `scene: 'list'|'form'`；`title` 可改为父级传入或由模块名+场景拼。
- [x] **Step 2:** 所有 API 调用改用 `props.moduleCode`；保存 `name` 用 Catalog/接口返回的模块中文名 + 「默认列表/表单」。
- [x] **Step 3:** 「表名」列改为显示字段池 `tableName` / 模块 `mainTable`（行级优先 `row.tableName`）。
- [x] **Step 4:** 分组下拉：form 场景改为可配置（一期可仍 basic/job，但从模块元数据或常量映射读取；至少不要在无 job 的模块强制两项）。**最低要求：** 未知分组码仍可手输或显示原值，不丢数据。
- [x] **Step 5:** `listDef.vue` / `formDef.vue` 改为 `<LayoutEditor module-code="hrEmp" scene="..." />`，行为与现网一致（回归人事资料定义）。

**验收:** 人事资料列表/表单定义页保存、加载、预览与改前一致；代码中无裸字符串 `'hrEmp'` 留在 layoutEditor 内部（除默认 prop 外）。
