# 业务模块表单/功能配置中心 — 可行性与方案

角色：架构分析。日期：2026-11-10。  
诉求：新增一模块，对各业务模块的**表单显示内容**与**功能**做可配置管理。

相关已有资产：`doc/分析文档/通用表单设计/`、人事资料定义（列表/表单）、`HrUiModuleCatalog`、`hr_ui_field_def` / `hr_ui_layout*`。

---

## 1. 结论（先说）

| 判断 | 说明 |
|------|------|
| **可行性：高** | 不必从零做低代码；仓库已有「模块码 + 字段池 + 布局方案 + Effective 运行时」骨架，且人员资料列表/表单已在消费。 |
| **推荐策略** | **扩展现有 UI 元数据体系**为「配置中心」，按模块登记推广；**禁止**另起第二套表单设计器 / EAV 动态列。 |
| **「功能配置」须划界** | 一期只做**展示与交互形态**（显隐、顺序、宽/占位、必填/只读、分组、控件类型、码表绑定）。按钮权限、审批流、业务校验规则另属权限/流程/领域服务，不塞进布局表。 |

---

## 2. 现状盘点

### 2.1 已具备

```text
物理表 (SysDatabase)
    │ Sync
    ▼
字段池 hr_ui_field_def (+ lang / field_scene)
    │ 白名单
    ▼
布局 hr_ui_layout / hr_ui_layout_field (+ 稀疏译文)
    │ Effective：个人方案 → 系统默认 → Builtin(全池)
    ▼
运行时：列表列 / 表单渲染（hrEmp 已接）
```

| 能力 | 落点 |
|------|------|
| 模块注册 | `HrUiModuleCatalog`（内存，**仅 `hrEmp`**） |
| 字段池维护 | `HrUiFieldDefService`、字段元数据页 |
| 列表/表单定义 UI | `reportDef/listDef`、`formDef` + `layoutEditor` |
| Effective API | `hrUiLayout/effective|fieldPool|saveDefault|saveMy` |
| 列表消费 | `hrms/emp/index.vue` |
| 表单消费 | `editEmp` + `empDynamicForm`（读 form Effective） |
| 多语言 | 池/布局译文 + `HrUiCulture` |
| 铁律 | 无实体字段不落库；布局不造列；码表走 `code_mstr` |

### 2.2 主要缺口（相对「全系统各业务可配」）

| 缺口 | 影响 |
|------|------|
| Catalog 仅 `hrEmp` | 其它模块调 Effective 会被 `HR_UI_MODULE_UNKNOWN` 拒绝 |
| 定义菜单绑死人事资料 | 无「按模块切换」的配置中心壳 |
| 各业务页未统一消费 Effective | 异动/离职/停职等仍多静态列与表单 |
| 「功能」语义未产品化 | 易与菜单按钮、流程节点、校验规则混淆 |
| 场景偏 list/form | 查询区、详情只读、导入模板列等未标准化 |
| 高级查询字段 | 人员资料已从布局/池生成；其它模块未强制同源 |

## 3. 「功能配置」范围建议

把诉求拆成三层，避免一次做成万能低代码：

| 层级 | 内容 | 建议归属 |
|------|------|----------|
| **L1 显示配置** | 字段显隐、顺序、宽度/栅格、分组、Label 多语、控件类型、码/lookup | **本模块（扩展现有布局）** |
| **L2 交互形态** | 必填、只读、默认折叠分组、列表是否可排序 | **本模块（布局字段属性）**；服务端校验仍以领域规则为准，布局 `required` 只能加强提示不能削弱安全 |
| **L3 业务功能开关** | 某按钮显隐、某流程是否启用、某规则开闭 | **不做进布局表**；用菜单权限 / 公司参数 / 流程定义 / 特性开关 |

产品话术建议对外叫：**「业务界面配置」**（字段与布局），不要叫「万能功能配置器」。

## 4. 目标架构（配置中心）

```text
┌─────────────────────────────────────────┐
│ 业务界面配置中心（新菜单壳）               │
│  选模块 → 选场景(list/form/…) → 设计器   │
│  （复用 layoutEditor / 字段池页）         │
└───────────────┬─────────────────────────┘
                │ ModuleCode
                ▼
        HrUiModuleCatalog（→ 可演进落表）
                │
     ┌──────────┴──────────┐
     ▼                     ▼
 字段池维护              布局默认/个人方案
     │                     │
     └──────────┬──────────┘
                ▼
     各业务运行时 GetEffective(module, scene)
```

### 4.1 新模块在产品上是什么

- **不是**每个业务再复制一套「人事资料定义」菜单。
- **是**一个配置中心入口：模块下拉（来自 Catalog）+ 场景 Tab（列表定义 / 表单定义）+ 现有编辑器。
- 权限：配置中心菜单 + `hrUiLayout/saveDefault` 等；业务用户仍可有个人方案（若产品保留）。

### 4.2 推广一个新业务模块的标准动作

1. Catalog 登记：`Code`、名称、主表、支持场景。  
2. Sync / 种子字段池（physical + 必要 lookup/computed）。  
3. 种系统默认 list/form 布局。  
4. 业务列表：列来自 Effective；排序/高级查询字段与池对齐（遵守 `page-list-sorting`、`adv-query-required`）。  
5. 业务表单：动态渲染器消费 form Effective；特殊控件走注册表（工号、组织树、照片等）。  
6. 多语言：池 Label + 布局稀疏覆盖。

## 5. 分期建议

| 阶段 | 目标 | 产出 |
|------|------|------|
| **P0 定界** | 产品确认只做 L1/L2；列出首批推广模块（建议：异动、离职、停职，或下一主数据） | 范围说明书 |
| **P1 配置中心壳** | 菜单「业务界面配置」；按模块切换复用现有 listDef/formDef；Catalog 可配置扩展（仍可先内存） | 一处维护多模块布局 |
| **P2 第二模块打通** | 选 1 个非 emp 模块全链路（池+默认布局+列表或表单消费） | 可复制的接入清单 |
| **P3 运行时组件化** | 抽出与 emp 解耦的 `DynamicListColumns` / `DynamicForm`（特殊字段注册表） | 新模块少写样板代码 |
| **P4 Catalog 落表（可选）** | 模块注册表 + 管理 UI，替代纯常量 | 非发版可增模块登记 |
| **P5 场景扩展（可选）** | `search` / `detail` / `import` 等 | 按业务需要再开 |

明确不做（与《通用表单设计》一致）：EAV、运行时造物理列、平行第二套元数据、把审批/权限塞进布局 JSON。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 业务页「半静态半动态」长期并存 | 新模块强制 Effective；旧页列入改造 backlog |
| 布局 required 与后端校验不一致 | 约定：后端校验为权威；布局必填仅 UX |
| 特殊字段（工号规则、管辖树）配丢 | 渲染器注册表 + 字段池 `origin`/`controlType` 锁定不可删 |
| Catalog 膨胀、无主表模块 | 允许 `MainTable` 空或仅 lookup 字段；无 Sync 的模块只维护手工池 |
| 与高级查询字段两套来源 | 规定：可筛字段 ⊆ 字段池（或布局可见集），禁止第三份硬编码清单 |
| 性能（每页 Effective） | 已有按用户方案；可加短缓存，键 = module+scene+user+culture |

## 7. 工作量量级（粗估）

| 项 | 量级 |
|----|------|
| P1 配置中心壳 + Catalog 扩 1～2 模块 | 小～中（复用编辑器） |
| P2 单业务列表或表单全接 Effective | 中（视字段特殊控件多少） |
| P3 通用动态表单/列表组件抽离 | 中 |
| 全 HR 业务铺开 | 大（按模块数线性，但单模块边际递减） |

相对「新做低代码平台」：成本低一个数量级，且与现库表、多语言、权限模型一致。

---

## 8. 验收（配置中心 MVP）

- [ ] 配置中心可选模块，编辑 list/form 默认方案并保存  
- [ ] 未知模块仍拒绝；已登记模块 Effective 返回正确文化 Label  
- [ ] 至少 2 个业务模块运行时消费布局（含现有 hrEmp）  
- [ ] 无实体字段无法配进可保存布局  
- [ ] 文档/规则：新列表须高级查询 + 排序；组织树列表筛选风格；本配置不替代权限与流程  

---

## 9. 建议决策

1. **立项名称**：业务界面配置中心（扩展 `HrUi*`，不新开表单引擎）。  
2. **首期边界**：L1 + L2；功能开关走 L3 既有体系。  
3. **实施顺序**：配置中心壳 → 第二模块样板 → 抽通用运行时 → 批量推广。  
4. **与现规则协同**：新列表仍遵守排序、高级查询、多语言；列表组织树默认隐藏规范不变。
