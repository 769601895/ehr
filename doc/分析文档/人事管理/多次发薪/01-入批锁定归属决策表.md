# 多次发薪：入批 / 锁定 / 归属决策表

> 适用模式：**例行一月一次**；奖金 / 离职结清 / 补发经常另发。  
> 口径来源：业务讨论共识 + 专家默认（标注「专家默认」处可改）。  
> 状态：**决策表已定稿**（第 8 节全部拍板）；可据此撰写正式需求与详细设计方案。

---

## 1. 先统一三个时间与一把锁

| 概念 | 含义 | 主要用于 |
|------|------|----------|
| **薪资月 / 税月（payMonth）** | 实际发放、扣缴申报所在月 | 银行出账、个税累计、实发类月报 |
| **归属月（belongMonth）** | 业务上这笔钱属于哪个月 | 成本、考勤归因、编制/人均、追溯分析 |
| **发薪批次（payRun）** | 一次审批、一次报盘的发放集合 | 锁定、支付、凭证、审计 |
| **个人范围锁** | `员工 + 薪资月 + 锁定范围` | 防止离职结清与例行重算；**不是**锁死一切发放 |

**硬约束（专家默认）**

1. 禁止用「员工 + 年月」作为工资唯一主键。  
2. 已确认批次禁止无痕修改；纠错走调整批 / 红冲。  
3. 发放可合并，归属可回溯；**两套月报口径并存**（实发 vs 归属成本）。

## 2. 批次类型总表

| 场景编码 | 场景 | 谁能进本批 | 与例行关系 | 锁定什么 | 发放月 payMonth | 归属月 belongMonth | 个税 | 社保公积金 | 月报口径 |
|----------|------|------------|------------|----------|-----------------|--------------------|------|------------|----------|
| R01 | 例行发薪 | 薪资月内「例行应发」且**未被例行范围锁**的在职/当月在职过人员（按公司截止规则） | 主批次；同薪资月通常仅一笔例行；**月中调薪在本批内分段算，不另开发放批**（见 §5） | 批次确认后：可锁本批明细；**不**因例行本身锁死旁路 | 例行发薪月 | 同薪资月（当月应得；分段只影响计算，不拆成两个发放月） | 并入该税月累计预扣 | **主扣批次**（专家默认在例行扣） | 实发月报 + 归属成本月报均计入 |

| B02 | 全年一次性奖金 | 同上；本年「全年奖单独计税」标记未占用（若选单独计税） | 独立批次；一般不并入例行 | 不锁例行；写入「本年已用全年奖优惠」标记（单独计税时） | 实际发放月 | 默认 = 发放月 | **可选**：单独计税 **或** 并入综合所得（批次/薪资项配置） | 默认不扣 | 实发看发放月；税申报按所选计税方式 |
| T01 | 离职结清（工资性） | 已发起离职且需结清工资性项目的人员 | **与当月例行互斥**：结清确认后加「例行范围锁」 | **锁：员工 + 结清覆盖的薪资月 + 范围=例行/工资性**（专家默认）；**不**锁奖金批、不锁已授权补发批 | 实际结清发放月 | 工资性：按应计区间拆归属（跨月则多行）；当月段归属当月 | 并入发放税月累计 | 专家默认：在结清批扣「截至离职应扣」；之后例行不再扣此人该月 | 实发看发放月；成本按归属月拆行 |
| T02 | 离职结清（解除补偿） | 同行可与 T01 同批不同薪资项，或独立子段 | 不影响例行互斥逻辑（随 T01 人员排除即可） | 同 T01 人员锁；税单独处理 | 实际发放月 | 归属终止月 / 发放月（财务口径，专家默认=发放月，成本可单列「补偿」） | **补偿金规则**：免税额度内不征，超额按一次性补偿，**不并入工资累计** | 不扣 | 实发单独列示；成本建议单独科目/统计项 |
| A01 | 少发/漏发补发（在职） | 在职或仍在例行范围内；存在历史少发差额 | **优先并入当月例行**作补发项目；量大或已过例行截止则开「同月补发批」与例行合并报盘或紧随支付 | 不因补发锁人；**禁止改写已关账历史月结** | 实际发放月（并进月结则=当月） | **必填历史归属月**（少发对应月） | 并入**发放税月**累计（专家默认） | 默认不扣（差额已在原月社保规则处理过则不再扣） | **双口径**：实发进发放月；成本/考勤归因进归属月 |
| A02 | 停发后补发（未办离职手续先停发，后补办） | 已停发、后补办手续需补历史应付；通常**已不在例行名册**；触发源为离职结算 **`StopPay` 等**，**不含停职单**（停职日起不计薪、不走 A02） | **独立补发批**；不并回历史例行重算；与 T01 分流（见注 B） | 补发确认后：对已补清的归属月打「该月工资性已结清」标记，防再重复补；**例行范围锁**按是否仍需进未来例行单独判断 | **记发放月**（资金/税） | **按停发覆盖区间按月拆行归属**（专家修正：不能只有发放月） | 并入发放税月累计 | 按补发区间规则配置；默认不在补发批重复扣全月社保，除非项上显式代扣 | 实发→发放月；成本/人事归因→各归属月；与「离职结清」分项统计 |

## 3. 入批互斥与锁定（细则）

| 条件 | 例行 R01 | 奖金 B01/B02 | 离职结清 T01/T02 | 在职补发 A01 | 停发补发 A02 |
|------|----------|--------------|------------------|--------------|--------------|
| 无锁，在职 | 可入 | 可入 | 不可（未走离职） | 可入 | 一般不适用 |
| 已确认 T01（例行范围锁） | **不可入** | 可入 | 不可重复结清同范围 | 仅当未结项显式允许 | 可入（补历史） |
| 已确认 A02 且该归属月已标结清 | — | — | — | 不可再补同月同项 | 不可重复 |
| 已确认例行 R01 未离职 | 不可再开第二笔例行（同薪资月同方案） | 可入 | 见下方「例行已支付后离职」 | 可并入或另开补发批 | — |

**锁定范围枚举（已拍板）**

| 锁定范围 | 挡住谁 | 仍允许 |
|----------|--------|--------|
| `RegularOnly` | 例行 R01 | 奖金、已授权补发、调整批 |
| `WageItems` | 例行 + 工资性补发 | 奖金、补偿金 |
| `AllPayroll` | 一切发放（慎用） | 仅调整/红冲（需高权限） |

| 配置项 | 建议键名 | 定稿 |
|--------|----------|------|
| 离职结清默认锁范围 | `TermSettleLockScope` | 默认 **`RegularOnly`**；公司/薪资组可改为 `WageItems`（或慎用 `AllPayroll`） |

**防漏发：** T01 确认时生成「未结项清单」。若配置为「结清一次结完工资性」，清单应为空才允许只加锁；若允许部分延期到例行，则**不得**加 `RegularOnly`，或锁改为「已结项级」而非整类例行锁。

**例行已支付后才办离职（已拍板）**

| 定稿 | 说明 |
|------|------|
| **结清只算差额 / 剩余项** | 不默认整月红冲重做 |
| 已发 &gt; 按离职日重算应付 | 结清批体现应扣回，或生成追扣待付；不自动冲掉整笔已支付例行 |
| 已发 &lt; 应付或尚有年假/补偿等 | 只发剩余项 + T02（如有） |
| 整月红冲重做 | 仅差错场景；**高权限**例外，不作默认路径 |

## 5. 月中调薪与薪资分段（专家默认）

### 5.1 先分清三种「调薪」，不要混进同一按钮

| 编码 | 类型 | 本质 | 进哪次发放 | 是否另开批次 |
|------|------|------|------------|--------------|
| S01 | **当月生效调薪**（含月中） | 薪资档案从生效日起换标准，当月例行按段折算 | **仍在 R01 例行一笔发出** | 否（算薪分段，不是多次发薪） |
| S02 | **下月生效调薪** | 生效日 ≥ 下月 1 日；本月例行仍用旧标准 | R01 用旧档；下月起用新档 | 否 |
| S03 | **追溯调薪**（生效日早于已发薪月） | 已发月份按新标准重算差额 | 差额走 **A01 补发**（或追扣），**禁止改已锁历史批次无痕** | 是（补发/调整批），或并入当月例行补发项 |

月中调薪的设计重点在 **S01：薪资档案有效期 + 例行引擎分段**，不是再开一次「调薪发薪」。

### 5.2 主数据：薪资档案必须带生效区间

| 字段（逻辑） | 说明 |
|--------------|------|
| 员工 + 薪资科目/薪级结构 | 基本工资、岗位工资等参与折算的项 |
| `effectiveFrom` / `effectiveTo` | 闭开或闭闭区间由公司统一；月中换档必有切日 |
| 金额 / 标准 | 该段有效标准 |
| 调薪原因 / 单据号 | 审计；与异动/调薪单关联 |

**禁止**只保留「当前一笔标准」而无历史区间——否则无法算月中、无法追溯、离职结清也对不上。

### 5.3 当月分段怎么算（S01）

例行 R01 对每个「按标准计」的薪资项：

1. 取该薪资月内，与员工在职区间、调薪切日相交的档案段（可能 2 段，极端多次调薪可多段）。  
2. 每段计算：`段标准 × 折算比例`。  
3. 段结果合计为该项本月应发；**支付仍一行（或一项）进同一例行批次**。  
4. 明细层建议保留**分段明细**（隐藏/可展开），供核对与审计；汇总层给银行报盘。

**折算分母（已拍板：三种预留 + 公司配置）**

系统**必须预留**下列三种算法，通过**公司参数**（建议再支持按**薪资组**覆盖）选择，禁止写死某一种：

| 配置值 | 模式 | 算法要点 | 典型适用 |
|--------|------|----------|----------|
| `AttendanceDays` | 计薪日历出勤日 | 段内应出勤日 / 月应出勤日 × 月标准 | 工厂、倒班、与考勤强绑定 |
| `CalendarDays` | 自然日 | 段内日历日 / 当月日历日 × 月标准 | 干部、制度简单 |
| `FixedMonthDays` | 固定月计薪日 | 段内计薪日 / 配置分母（默认 **21.75**，分母可配）× 月标准 | 对齐月计薪天数、降低大月小月波动 |

**解析优先级（专家默认）：** 员工所属薪资组参数 → 否则公司（`SiteCode`）参数 → 未配置则报错，不静默按自然日兜底。

**可选扩展（非必须一期）：** `NoProration`（整月新标准）——仅当公司制度书面启用；默认不开放，避免争议。

入职/离职当月与调薪叠加时：**切点 = 在职日起止 ∩ 档案生效区间 ∩ 薪资月**，先求交集再折算，避免重复或空窗。折算分母与上表同一套公司/薪资组配置。

### 5.4 哪些项折算、哪些项不折算

| 项类 | 专家默认 |
|------|----------|
| 月薪基本工资、岗位工资、固定津贴（按月标准） | **按段折算** |
| 按出勤/计件/提成已按事实计算的项 | **不按调薪段折**（跟考勤/业务事实） |
| **加班费** | 小时/日数跟考勤事实；**基数取「加班发生日」当天有效薪资档案**（已拍板，见 §5.5.2），不按整月一段标准，也不按发薪月期末一刀切 |
| 全月一次性津贴（如交通包干且制度写明不折） | 按制度：常取**月末标准**或**出勤≥N 天用新档** |
| 社保公积金基数 | **不随月中工资标准自动切两段**；按公司「基数生效规则」（常：下月/下季/次年调整）。调薪 ≠ 当月改基数 |
| 个税 | 仍按税月累计；分段只影响应税收入合计，不按段分别报税 |

### 5.5 与多次发薪其它场景的衔接

| 场景 | 调薪如何影响 |
|------|----------------|
| R01 例行 | S01 在批内分段；一次支付 |
| B01 奖金 | **不分段**；按公司参数 `BonusBaseRateMode` 取**规则日单一标准**（见 §5.5.1） |
| T01 离职结清 | 结清覆盖天数内同样按档案段折算；切日在离职日前则旧+新两段都进结清 |
| A01 少发漏发 | 若因「当时未按调薪算」→ 属 S03，差额补发，belongMonth=原薪资月 |
| A02 停发补发 | 补算历史月时，按该月当时有效档案段重算，再汇总到发放月支付 |
| 月中调薪后又离职 | 先档段折算，再按离职日截断；结果进 T01，并加例行范围锁 |

#### 5.5.1 奖金基数遇调薪（已拍板：参数配置 + 默认期末）

| 原则 | 定稿 |
|------|------|
| 是否按月中调薪分段折算奖金基数 | **否（默认且一期不提供加权分段）** |
| 取数方式 | 规则日当天薪资档案上的**一个标准** |
| 配置项 | `BonusBaseRateMode` |
| 可选值 | `PeriodEnd`（**推荐默认**：考核期/归属期末日）、`PeriodStart`（期初）、`GrantDate`（授予/评定日）、`PayDate`（发放日） |
| 解析优先级 | 薪资组 → 公司 `SiteCode` → 未配置报错 |
| 一期不做 | `WeightedAverage`（按调薪段加权）——有书面制度再扩展 |

与基本工资（S01 分段）刻意分离：工资按在职天数吃饭；奖金按规则取基数。

#### 5.5.2 加班费遇调薪（已拍板：发生日档案）

| 原则 | 定稿 |
|------|------|
| 加班时长 | 来自考勤/加班单（事实），不按调薪段重折小时 |
| 加班费**基数** | 取**该笔加班发生日**当天 `hr_pay_emp_rate`（或等价档案）有效标准 |
| 月中调薪 | 调薪前发生的加班用旧档；调薪日及之后发生的加班用新档（含当日规则与档案闭开区间一致） |
| 与奖金基数 | **不同**：奖金用 `BonusBaseRateMode` 单点；加班用发生日逐笔取档 |
| 追溯调薪 S03 | 若加班已按旧档随例行发出，差额进 retro/A01，**不改**已确认批次无痕 |
| 一期不做 | 加班基数公式细节（是否含津贴、除数 21.75/应出勤等）→ 算薪引擎/考勤对接时另开专节；本条只钉**取档时点** |

### 5.6 调薪决策简表

| 条件 | 系统行为 |
|------|----------|
| 调薪单生效日在本薪资月内，且例行未确认 | R01 按 S01 分段重算 |
| 生效日 ≥ 下月 1 日 | S02；本月 R01 不引用新档 |
| 生效日落在已确认/已支付的薪资月 | S03；生成差额 → 待付补差（补或扣），不改历史锁批；**支付路径见公司参数** |
| 同一薪资月多次调薪 | 多段折算后合计；仍一次例行发放 |
| 调薪是否单独发一笔现金 | 由参数 `RetroPayMode` 决定（见下），禁止同一差额两条路径都付 |

**追溯差额支付路径（已拍板：公司参数配置）**

| 配置项 | 建议键名 | 取值 | 含义 |
|--------|----------|------|------|
| 追溯补差支付模式 | `RetroPayMode` | `MergeNextRegular` | 差额进待付队列，**并入下一次（或当月未确认）例行 R01** 发放/追扣 |
| | | `ImmediateAdjBatch` | 差额生成后**可立即开 A01/调薪补差批**单独支付 |
| | | `Both`（**推荐默认**） | **默认走并入例行**；持权限者可改为立即开补发批；同一差额互斥，只能选一条路径 |
| 立即补发权限（已拍板） | 权限点如 `hrPayRetroImmediate` | — | `RetroPayMode=Both` 或 `ImmediateAdjBatch` 时，**开立即补发批必须单独授权**；无权限者仅能并入例行 |
| 追扣不足时 | `RetroDeductOverflow` | `DeferNext` / `CreateDeductBatch` 等 | 本期应发不够扣时的处理（可二期；一期可先 `DeferNext`） |

**关键参数未配置（已拍板）：** 薪资组 → 公司 `SiteCode` → **未配置则强制报错**，禁止算薪/开批；**不允许**系统级静默默认值（与「未配置归属公司就失败」一致）。

涵盖至少：折算分母、`RetroPayMode`、`BonusBaseRateMode`、`TermSettleLockScope`、`BonusMergeBankFile`（若该厂启用奖金发薪）。

**防重发：** 待付补差记录状态机至少含 `PendingMerge` / `PendingImmediateBatch` / `InPayRun` / `Paid` / `Cancelled`；进入例行或进入补发批后锁定，另一路径不可再领同一 `deltaId`。

### 5.7 易偏点（对照常见误设计）

| 误法 | 问题 | 正确方向 |
|------|------|----------|
| 月中调薪再开一次发薪批 | 与「例行一次」冲突，税与报盘复杂 | 批内分段，一次支付 |
| 只改当前标准、无生效区间 | 无法追溯、离职/补算失真 | 档案区间化 |
| 追溯调薪直接改历史月结 | 破坏关账与已申报 | S03 → A01 |
| 社保基数跟月中工资同步切两段 | 与社保申报实务不符 | 基数单独生效规则 |
| 分段后 belongMonth 拆成两个月 | 调薪不是跨月归属 | 归属仍在当月薪资月 |

## 6. 个税 / 社保速查（专家默认）

| 场景 | 个税 | 社保公积金 |
