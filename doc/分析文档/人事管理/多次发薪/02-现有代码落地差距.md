# 多次发薪：对照现有代码的落地差距

> 对照文档：[01-入批锁定归属决策表.md](./01-入批锁定归属决策表.md)（已定稿）  
> 勘察范围：`Admin.NET` HR 实体/服务、`Web/src/views/hrms/companyParam`、离职/停职、公司参数 SQL；分析文档中的人事月报/离职方案。  
> 日期：2026-11-11

---

## 1. 总判读

| 结论 | 说明 |
|------|------|
| **薪资核算与发薪域基本未建** | 无 PayRun、工资明细、薪资档案区间、个税台账、银行报盘等实体与服务 |
| **可复用的是「厂别取参骨架」+「离职结算钩子」** | `HrCompanyParam` + `HrCompanySiteResolveService`；离职 `hr_emp_leave_pay_cmd` |
| **人事月报是上游输入，尚未落代码** | 仅有详细设计，无 `HrEmpMonth*` 实体/API |
| **决策表能力绝大多数为 MISSING** | 落地等于新建薪资域，而不是小改公司参数字段 |

整体成熟度：**人事侧已具备部分「给算薪用的信号」；算薪/发薪引擎本身从 0 开始。**

## 2. 现有相关能力（可承接）

| 能力 | 路径 / 落点 | 与决策表关系 |
|------|-------------|--------------|
| 公司参数主表 + UI | `Entity/HrCompanyParam.cs`；`Service/Hr/CompanyParam/*`；`Web/.../companyParam/` | 可扩展决策表 §8.1 参数；现有字段偏人事/考勤/社保月报，**无**发薪专用键 |
| 部门 → SiteCode | `HrCompanySiteResolveService` | 符合公司参数解析规则；发薪取参应复用，禁止旁路 |
| 考勤月界相关参数 | `AttCloseDay`、`PayrollAttMonth`、`RequiredAttDayMode`、入离职日考勤 | 人事月报/考勤月用；**不是**调薪折算分母（勿直接等同 `AttendanceDays`） |

| 离职薪资结算码 | `LeaveSalarySettle`：`NormalPay` / `StopPay` / `AutoNoPay`（方案+码表） | 可映射 T01 入批与 A02「停发后补发」信号；**算薪未消费** |
| 离职结算指令表 | `HrEmpLeavePayCmd`（`settle_code`、`pay_period`、Active/Consumed/Voided） | 注释写明「算薪后接消费」；是 T01/停发与例行衔接的**现成钩子** |
| 人员薪酬类别 | `HrEmployee.emp_sal`（长度 2） | 仅类别码，**非**薪资标准档案，无生效区间 |
| 停职单 | `HrEmpSuspend` | 人事停职；**无**与发薪锁/停发补发批的自动联动 |
| 组织工资率 | `CcMstr.CcWageRate` | 组织属性，非员工薪资档案 |
| 已删除的旧薪资参数 | `doc/sql/2026-11-02/02-HrCompanyParam删除薪资三项.sql` | 曾有奖惩/核定薪资相关列，已删；说明薪资参数曾试探后收回，**勿假设仍有算薪配置** |
| 人事月报设计 | `doc/分析文档/人事管理/人事月报/` | 预关账名单+快照，供薪酬消费；**代码未实现** |
| 多次发薪决策 | 本目录 `01-*.md` | 规则已定稿，待工程化 |

**明确不存在（抽样）：** `PayRun` / `Payroll` / 工资单实体、薪资组主数据、带 `effectiveFrom/To` 的薪资档案、个税累计台账、补发待付队列、银行报盘、`RetroPayMode` 等参数键、立即补发权限点。

## 4. 建议落地分层（差距 → 工程顺序）

在不推翻决策表的前提下，建议分四层，避免一上来做完整报税引擎：

| 优先级 | 层 | 内容 | 依赖现有 |
|--------|----|------|----------|
| **P0** | 域模型骨架 | PayRun + 明细（含 payMonth/belongMonth/批次类型）+ 个人范围锁 + 支付状态；消费/回写 `HrEmpLeavePayCmd` | 离职指令、SiteCode 解析 |
| **P0** | 公司参数扩展 | §8.1 键加入 `HrCompanyParam`（或明细表）+ 码表 + 公司参数 UI 分区「薪资参数」；未配报错 | 现有 CompanyParam 模式 |
| **P1** | 薪资档案 | 员工标准区间表 + 调薪单写区间；S01 分段（三折算模式） | 建议先有计薪日历/应出勤来源（可与考勤参数对齐） |
| **P1** | 例行 R01 + T01 | 入批互斥、`TermSettleLockScope`；离职结清批 | PayCmd、`LeaveSalarySettle` |
| **P2** | A01/A02 + Retro | 补发、追溯队列、`RetroPayMode`、立即补发权限 | 锁与例行 |
| **P2** | B01/B02 | 奖金批、`BonusBaseRateMode`、合并报盘开关 | 档案规则日取数 |
| **P3** | 个税累计 / 报盘 / 成本双月报 | 税台账、银行文件、报表口径 | 多批次稳定后 |
| **并行** | 人事月报 | 按已有设计实现，作为 R01 权威名册 | `AttCloseDay`/`PayrollAttMonth` |

**薪资组：** 决策表要求组级覆盖；若一期只有少量厂别差异，可 **P1 仅公司级参数**，P2 再引入薪资组主数据与 `emp` 归属，避免阻塞 P0。

## 5. 风险与红线（对照代码现状）

1. **不要**把 `RequiredAttDayMode` 直接当调薪折算分母——用途是考勤应出勤，改语义会拖垮考勤/月报。  
2. **不要**在无 PayRun 前让离职 `StopPay` 只改文档；补发 A02 必须有批次与归属月，否则与决策表冲突。  
3. **不要**用 `emp_sal` 冒充薪资组或薪资标准。  
4. 扩展公司参数时走既有 SiteCode 解析；跨管辖厂别禁止静默默认（与现规则一致）。  
5. 人事月报未建时，R01 若用「实时花名册」须在方案中标明临时策略，避免与日后冻结名册两套口径。
