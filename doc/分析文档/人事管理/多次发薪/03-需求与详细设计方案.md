## 1. 意图与为什么现在做

业务模式已确认：**例行一月一次**；奖金、离职结清、补发（含停发后补发）**经常另发**。月中调薪在例行批内分段，不另开「调薪发薪」。

当前代码侧：

- 有厂别取参（`HrCompanyParam` + `HrCompanySiteResolveService`）；
- 有离职结算指令 `hr_emp_leave_pay_cmd`，**无人消费**；
- **无** PayRun、薪资档案区间、个税累计、报盘；人事月报仅有设计未落库。

本方案交付的是**可分期落地的薪资发放域**：先批次与锁与参数，再档案与例行/结清，再补发/奖金，最后税与报盘。

成功标准：

1. 同人同月可进多批；禁止「员工+年月」唯一工资单。  
2. 离职结清与例行互斥（范围锁）；补发双口径（发放月 / 归属月）可对账。  
3. 调薪三段（当月分段 / 下月生效 / 追溯补差）行为符合决策表；折算分母等关键策略公司可配。  
4. 取参走 SiteCode 解析；关键参数未配**报错**；列表/多语言/管辖遵循项目规则。

## 3. 目标 / 非目标 / 反目标

### 3.1 按分层目标

| 层 | 目标 |
|----|------|
| **P0** | PayRun/明细/锁/支付状态骨架；扩展公司参数 §8.1；消费/回写 `HrEmpLeavePayCmd`；T01 开批互斥例行占位；权限与列表基建 |
| **P1** | 薪资档案区间；折算三模式；R01 例行算薪（固定项+分段）；T01 结清+`TermSettleLockScope`；与人事月报名册对接 |
| **P1.1 / 与考勤对接** | 加班费按发生日取档（C16）；加班基数除数/组成公式另开专节，不阻塞 P0 |
| **P2** | A01/A02；追溯差额队列+`RetroPayMode`；B01/B02+`BonusBaseRateMode`；`BonusMergeBankFile`；可选薪资组覆盖 |
| **P3** | 税月累计台账；社保主扣落地；银行报盘与回写；实发/归属双月报；红冲调整批完善 |

### 3.2 非目标（明确不做或后置）

| 不做 | 说明 |
|------|------|
| 双周薪/一周多例行排程 | 非当前模式 |
| 把奖金算进例行公式糊成一行 | 禁止 |
| 追溯改已确认批次无痕 | 禁止 |
| 占用 `RequiredAttDayMode` 当调薪折算分母 | 禁止混用 |
| 用 `emp_sal` 当薪资组或标准档案 | 禁止 |
| 股权激励等特殊所得完整税引擎 | 后置 |
| 加权平均奖金基数 | 一期不做 |
| 人事月报本身 | 并行模块，本方案只定义消费契约 |

### 3.3 反目标

- 一员工一月只能一张工资单。  
- 离职结清后仍进例行或锁死一切奖金。  
- 补发只有发放月、成本月报永远对不齐。  
- 参数未配却静默按自然日/某厂默认算薪。  
- 无档案历史却宣称支持月中调薪。

## 5. 核心概念与状态机

### 5.1 批次类型

与决策表一致：`R01` `B01` `B02` `T01` `T02` `A01` `A02`。  
T02 可与 T01 同批不同薪资项（`CompSegment=Wage|Severance`），或独立批。

### 5.2 PayRun 状态（建议）

```text
Draft → Calculated → Confirmed → Paying → Paid
                 ↘ Voided
Confirmed 后禁止改明细；纠错 → 调整批 / 红冲批（P3 完善，P1 至少禁止改）
```

| 状态 | 含义 |
|------|------|
| Draft | 开批、圈人 |
| Calculated | 已算或已导入明细 |
| Confirmed | 业务确认；写锁/税台账（P3）入口 |
| Paying | 报盘中（P3） |
| Paid | 支付完成 |
| Voided | 作废（未支付） |

### 5.3 个人范围锁

表逻辑键：`EmpId + PayMonth + LockScope`（+ `SiteCode`）。  
来源：T01 确认写入；范围取 `TermSettleLockScope`（默认 `RegularOnly`）。  
入 R01 前必须检查锁。

### 5.4 追溯待付（P2）

`hr_pay_retro_delta`：差额、belongMonth、状态  
`PendingMerge` / `PendingImmediateBatch` / `InPayRun` / `Paid` / `Cancelled`  
同一 `deltaId` 仅一条支付路径。

## 7. 公司参数扩展（P0）

在 `HrCompanyParam` **新增列**（或等价参数明细表；推荐主表列与现 UI 分区一致，降低一期复杂度）。

| 参数键 / 字段 | 类型建议 | 默认 | 说明 |
|---------------|----------|------|------|
| `PayProrationMode` | 码 | **必填无静默默认** | `AttendanceDays` / `CalendarDays` / `FixedMonthDays` |
| `PayFixedMonthDays` | decimal | 21.75 | 仅 Fixed 模式 |
| `RetroPayMode` | 码 | `Both` | MergeNextRegular / ImmediateAdjBatch / Both |
| `BonusBaseRateMode` | 码 | `PeriodEnd` | PeriodEnd / PeriodStart / GrantDate / PayDate |
| `TermSettleLockScope` | 码 | `RegularOnly` | RegularOnly / WageItems / AllPayroll |
| `BonusMergeBankFile` | bool/int | false | 是否允许奖金与例行合并报盘 |

**禁止**改写 `RequiredAttDayMode` 语义。

权限点（P0/P2）：

| 权限 | 用途 |
|------|------|
| `hrPay/*` 模块权限 | 批次 CRUD、确认等 |

| `hrPayVoidPaid` 等高权限 | 红冲（P3，可预留） |

## 9. 关键业务规则（实现必须遵守）

| # | 规则 |
|---|------|
| R1 | 明细必有 PayMonth、BelongMonth；禁止只用一个「月份」字段冒充两者 |
| R2 | Confirmed 批次禁止无痕改金额；纠错走新批 |
| R3 | T01 Confirmed → 写 `hr_pay_emp_lock`；R01 入批过滤锁 |
| R4 | 消费 PayCmd 须幂等 MarkConsumed；作废离职指令则不可再消费 |
| R5 | S01 分段合计进同一 R01 支付；分段明细可查 |
| R6 | S03 不改历史 Confirmed 批；只生成 retro delta |
| R7 | A02 归属强制按自然月多行 |
| R8 | 奖金基数按 `BonusBaseRateMode` 单点取档，不分段 |
| R8a | 加班费：时长=考勤事实；**基数=加班发生日档案**（C16）；月中调薪前后加班可分属旧/新档 |
| R9 | 社保：R01（或结清）主扣；B01/B02 默认不扣 |
| R10 | 取参必须经 SiteCode 解析；管辖外不可操作该厂批次 |
| R11 | 例行已 Paid 后离职：T01 只处理差额/剩余项 |
| R12 | `BonusMergeBankFile=true` 仅合并报盘文件，不合并算薪批次身份 |

`LeaveSalarySettle` 映射：

| settle | 发薪行为 |
|--------|----------|
| NormalPay | 可入 T01；计薪至离职日（含，与离职方案一致） |
| StopPay | 当月例行排除；可走 A02（**仅离职停发**） |
| AutoNoPay | 当月不发；默认不进 A02 队列（人工高权限例外另议） |

**停职（`hr_emp_suspend`，C15）：**

| 点 | 定稿 |
|----|------|
| 是否 A02 触发源 | **否** |
| 计薪 | 停职日起不算薪资（名册排除或应发为零，按实现与人事月报一致） |
| 与离职 StopPay | 分流：停职=期间不计薪；StopPay=离职结算码上的停发，后续可补发 |

## 12. 分期交付与验收

### P0 验收

- [ ] 可开多类型批次；同人同月多行不撞唯一工资单约束  
- [ ] 公司参数薪资区可维护；缺 `PayProrationMode` 等关键项时开批/确认报错  
- [ ] T01 确认写 `RegularOnly`（或配置范围）锁；R01 不再纳入该人  
- [ ] PayCmd Active → 确认后 Consumed
