# 多次发薪 P0 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地薪资发放域 P0：发薪批次骨架、个人范围锁、公司薪资参数、消费离职 PayCmd，使 T01 确认后例行不可再纳入同一人。

**Architecture:** 新建 `hr_pay_*` 表与 `HrPayRunService`；扩展 `HrCompanyParam` 薪资区字段；确认 T01 时同事务写 `hr_pay_emp_lock` 并将 `hr_emp_leave_pay_cmd` 置 `Consumed`。P0 不算完整公式引擎，明细金额以录入/导入为准，Confirm 前金额必填。

**Tech Stack:** Admin.NET + SqlSugar（HR 库）；Vue3 + Element Plus + vxe-grid + `useAdvQuery`；vue-i18n；公司参数既有页扩展。

**Spec:** [03-需求与详细设计方案.md](./03-需求与详细设计方案.md)（已批准）；规则权威 [01-入批锁定归属决策表.md](./01-入批锁定归属决策表.md)。

## Global Constraints

- 模块码 `hrPay`；表前缀 `hr_pay_*`；SQL 进 `doc/sql/{yyyy-MM-dd}/`。
- 禁止「员工+年月」唯一工资主键；明细必有 `PayMonth` + `BelongMonth`。
- 取参经 `HrCompanySiteResolveService` / 批次上 `SiteCode`；关键薪资参数未配 → 开批或 Confirm **报错**。
- Confirmed 不可 Void；仅 Draft/Calculated 可作废；PayCmd Consumed 不因作废自动回 Active。
- T01 一期：一次结清语义；Confirm 即按 `TermSettleLockScope` 加锁（P0 无项级锁）。
- 停职不计薪、不进 A02；A02/奖金/档案分段属 P1+，本计划不实现。
- 列表：`page-list-sorting`、`adv-query-required`、`list-org-tree-panel`、`i18n-multilang-required`。

## Review Focus

1. 缺 `PayProrationMode`（或其它必填薪资参）时 Create/Confirm 失败，无静默默认。  
2. 同 `SiteCode+PayMonth` 已有未作废 R01 时再开 R01 被拒。  
3. T01 Confirm 后同人同月 R01 加行失败（锁生效）；B01 仍可开（锁为 RegularOnly）。  
4. Confirm 与写锁、PayCmd Consumed **同事务**；中途失败无半锁。  
5. 管辖外 `SiteCode` 不可开批/确认。

### Task 4: HrPayRunService 核心 API

**Files:**
- Create: `Admin.NET/**/Service/Hr/Pay/Dto/HrPayRunDto.cs`
- Create: `Admin.NET/**/Service/Hr/Pay/HrPayRunService.cs`
- Create: `Admin.NET/**/Service/Hr/Pay/HrPayRunFieldRegistry.cs`（高级查询白名单，可先少量字段）

**Interfaces:**
- Produces API（动态 API）：`Page`、`Get`、`Create`、`Update`（仅 Draft）、`Void`（Draft/Calculated）、`AddLines`、`RemoveLines`、`ImportLines`（可 P0 简化为批量 AddLines）、`Calculate`（P0：有行且金额齐则标 Calculated）、`Confirm`
- Consumes: `HrPayParamGuard`、`HrPayLockService`、SiteResolve/管辖校验（对齐离职/人事月报：操作人须能操作该 SiteCode）

**Confirm 规则（P0）：**
1. `EnsureReadyAsync(site)`  
2. 状态 Calculated（或允许 Draft 若已有完整金额——**定：必须先 Calculated**）  
3. 每行 Amount 明细合计可解析  
4. 若 RunType=T01：对每个 Emp 写锁（scope=公司 `TermSettleLockScope`）；MarkPayCmdConsumed  
5. 状态→Confirmed；同事务  

**Create R01：** 同 Site+PayMonth 已有非 Void R01 → 报错。  
**AddLines R01：** 有挡板锁 → 报错。  
**Void：** Confirmed → 报错。

- [ ] **Step 1:** DTO + Page（`BasePageInput` + OrderBuilder + Filter Registry）。

- [ ] **Step 2:** Create/Update/Void/AddLines/RemoveLines/Calculate。

- [ ] **Step 3:** Confirm 事务实现（上列规则）。

- [ ] **Step 4:** 验收脚本或手工：T01 Confirm → 锁存在且 PayCmd Consumed；再 R01 AddLines 同人失败。

- [ ] **Step 5:** Commit：`feat(hrPay): pay run service P0`
