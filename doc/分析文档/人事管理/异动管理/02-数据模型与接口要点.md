# 异动管理 — 数据模型与接口要点

> 配合 [01-需求与方案总览.md](./01-需求与方案总览.md)  
> 一期主路径：**独立业务表 + 模块内审核 + 本模块 Apply/Job**。  
> **不**依赖审批流程、`hr_wf_effect_*`、测试用 `hrEmh` 表单。

---

## 1. 状态机

| 状态码 | 名称 | 说明 |
|--------|------|------|
| `Draft` | 草稿 | 可改、可删、可提交 |
| `InReview` | 审核中 | 只读；可通过/驳回 |
| `Approved` | 已通过待生效 | 只读；等待写回 |
| `Effective` | 已生效 | 主档已按「后」更新；可撤销 |
| `Rejected` | 已驳回 | 只读；不参与拦截 |
| `Voided` | 已作废 | 撤销后；不参与拦截 |

```text
Draft --提交--> InReview --通过--> Approved --写回成功--> Effective
                InReview --驳回--> Rejected
Effective --撤销--> Voided
Draft --删除--> （软删 IsDelete）
```

**参与发起拦截**：`Draft`、`InReview`、`Approved`、`Effective`。  
**不参与**：`Rejected`、`Voided`。

库：HR 业务库（`ApplicationConst.HrDbConfigId`）。

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK | |
| chg_no | nvarchar(50) | 单号唯一，自动产生 |
| emp_id | nvarchar(50) | 工号 |
| emp_name | nvarchar(100) | 姓名快照 |
| chg_date | date | 异动日期 |
| chg_type | nvarchar(50) | 类别代码 |
| chg_reason | nvarchar(500) | 原因 |
| status | nvarchar(20) | 状态码 |
| submit_time / submit_user_id | | |
| approve_time / approve_user_id | | 通过或驳回 |
| reject_reason | nvarchar(500) | |
| effective_time | datetime | 实际写回完成时间 |
| void_time / void_user_id / void_reason | | |
| applied_columns | nvarchar(500) | 可选；Apply 实际写入的 db_column 列表，供撤销 |
| 审计列 | | EntityBase |

索引：`(emp_id, chg_date)`、`status`、`chg_no` 唯一。

### 2.2 异动明细 `hr_emp_chg_line`

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK | |
| chg_id | bigint | |
| field_key | nvarchar(64) | 如 ccCode、postId |
| db_column | nvarchar(64) | 快照：cc_code、post_id |
| label | nvarchar(256) | 显示名快照 |
| value_before | nvarchar(max) | 异动前 |
| value_after | nvarchar(max) | 异动后；空=不写该列 |
| sort_no | int | |

同一 `chg_id` 下 `field_key` 唯一。

一期固定两行（可种子/开单生成）：部门 `ccCode`→`cc_code`（after 必填）；岗位 `postId`→`post_id`（after 可空）。

### 2.3 可改字段配置 `hr_emp_chg_field`（一期可只做种子、不做维护页）

| 列 | 说明 |
|----|------|
| field_key | 对应 hrEmp 字段池 |
| enabled / sort_no / required | |
| 审计列 | |

一期种子：`ccCode`（required=1）、`postId`（required=0）。

### 2.4 历史 `h_emh_hist`

生效成功时插入一行（映射 `chg_no`→`emh_nbr`，`chg_date`→`emh_date`，部门岗位前后值等）。不替代 `hr_emp_chg` 作为在途权威。

### 2.5 写回日志（建议）`hr_emp_chg_apply_log`

chg_id、action（Apply/Void）、success、message、time。一期可用系统日志代替。

## 4. 核心校验与写回

### 4.1 保存草稿 / 提交前拦截（R15）

对目标 `emp_id`（不含本单）：

1. 存在 `InReview` → 拒（R5）。  
2. 存在拦截状态且 `chg_date > 本次` → 拒（R6）。  
3. 同日拦截状态（含 Effective）已有单 → 拒（R7/R13）。  
4. 拦截状态内最多一张 Draft（不含本单）。

换人、改日期时重跑。打开已存草稿默认不按主档重置；换人或显式「按主档重载」才刷新前后默认值。

### 4.2 提交

- 仅 `Draft`。  
- 工号、异动日期、类别、部门 after 非空。  
- → `InReview`。

### 4.3 通过 / 驳回

- 仅 `InReview`；需审核权限。  
- 通过 → `Approved`；若 `chg_date≤今天` 触发一次 Apply。  
- 驳回 → `Rejected`，可填原因。

### 4.4 Apply

前置：`Approved` 且 `chg_date≤业务今天`。

1. 锁单；读明细。  
2. `value_after` 非空才写对应 `db_column`（R11）。  
3. 记 `applied_columns`；状态 `Effective`；写 `h_emh_hist`。  
4. 失败保持 `Approved`，Job 重试。

### 4.5 Void

前置：`Effective`；无更晚拦截状态单据（R8）。  
按本单 `value_before` 回滚 `applied_columns`（或非空 after 对应列）；→ `Voided`。

## 5. API 要点

服务：`HrEmpChgService`（及可选 `HrEmpChgFieldService`）。

| 接口 | 说明 |
|------|------|
| Page | `BasePageInput` + `OrderBuilder` |
| Detail | 主表 + 明细 |
| SaveDraft | 新增/更新；可选 `reloadFromEmp` |
| DeleteDraft | 仅 Draft |
| Submit / Approve / Reject / Void | 状态流转 |
| PreviewDefaults | 工号 → 表体默认前后值 |

权限建议：`HrEmpChg:Add|Update|Delete|Submit|Approve|Reject|Void`（与项目惯例对齐）。

前端建议：

| 页面 | 路径 |
|------|------|
| 列表 | `Web/src/views/hrms/empChg/index.vue` |
| 编辑 | `Web/src/views/hrms/empChg/component/editChg.vue` |
| API | `Web/src/api/hrms/hrEmpChg.ts` |
