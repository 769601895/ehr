# 异动管理 — 数据模型与接口要点

> 配合 [01-需求与方案总览.md](./01-需求与方案总览.md)  
> 表名/字段名为方案建议，实现时可微调但须保持语义与状态机不变。

---

## 1. 状态机

| 状态码 | 名称 | 说明 |
|--------|------|------|
| `Draft` | 草稿 | 可改、可删、可提交 |
| `InReview` | 审核中 | 只读；可通过对驳回 |
| `Approved` | 已通过待生效 | 只读；等待写回 |
| `Effective` | 已生效 | 主档已按「后」更新；可撤销 |
| `Rejected` | 已驳回 | 只读；不参与拦截 |
| `Voided` | 已作废 | 撤销后；不参与拦截 |

```text
Draft --提交--> InReview --通过--> Approved --写回成功--> Effective
                InReview --驳回--> Rejected
Effective --撤销--> Voided（同时回滚主档）
Draft --删除--> （物理删或软删，推荐软删 IsDelete）
```

**参与发起拦截的状态**：`Draft`、`InReview`、`Approved`、`Effective`。  
**不参与**：`Rejected`、`Voided`。

## 2. 表设计

库：与 HR 业务库一致（`ApplicationConst.HrDbConfigId` / `ehr`）。

### 2.1 异动可改字段配置 `hr_emp_chg_field`

全系统一份清单（无「异动类型」维度）。

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK | |
| field_key | nvarchar(64) | = `hr_ui_field_def.field_key`，且 `module_code='hrEmp'` |
| enabled | bit | 是否出现在新开单表体 |
| sort_no | int | 展示序 |
| required | bit | 异动后是否必填（默认 0；部门一期可按需 1） |
| 审计列 | | 同 `EntityBase` |

约束：

- `field_key` 唯一。
- 仅允许 `origin='physical'` 且 `db_column` 非空、主表 `h_emp_mstr` 的池字段。
- 禁止配置：工号 `empId`、内部主键、纯计算/lookup 无写回列的字段（如单独的 `ccDesc`）。

一期种子：

| field_key | db_column | 说明 |
|-----------|-----------|------|
| ccCode | cc_code | 部门 |

### 2.2 异动主表 `hr_emp_chg`

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK | |
| chg_no | nvarchar(50) | 异动单号，唯一，自动产生 |
| emp_id | nvarchar(50) | 工号 |
| emp_name | nvarchar(100) | 姓名快照（开单时） |
| chg_date | date | 异动日期（写回与拦截用此日期） |
| chg_type | nvarchar(50) | 异动类别代码值 |
| chg_reason | nvarchar(500) | 异动原因 |
| status | nvarchar(20) | 状态码 |
| submit_time / submit_user_id | | 提交 |
| approve_time / approve_user_id | | 通过或驳回 |
| reject_reason | nvarchar(500) | 驳回原因（可选） |
| effective_time | datetime | 实际写回完成时间 |
| void_time / void_user_id / void_reason | | 撤销 |
| 审计列 | | |

索引建议：`(emp_id, chg_date)`、`status`、`chg_no`唯一。

### 2.3 异动明细 `hr_emp_chg_line`

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK | |
| chg_id | bigint | 主表 id |
| field_key | nvarchar(64) | |
| db_column | nvarchar(64) | 开单时从字段池快照，避免池变更导致历史对不上 |
| label | nvarchar(256) | 开单时显示名快照 |
| value_before | nvarchar(max) | 异动前（统一字符串存储；日期/数字按不变文化格式） |
| value_after | nvarchar(max) | 异动后 |
| sort_no | int | |

同一 `chg_id` 下 `field_key` 唯一。

### 2.4 写回日志（建议）`hr_emp_chg_apply_log`

便于排障：chg_id、action（Apply/Void）、success、message、time。一期可先打系统日志，表可选。

## 3. 单号规则（建造方默认）

- 格式：`CHG` + `yyyyMMdd` + 4 位流水，例 `CHG202610200001`。
- 按日流水；并发用库内取号或事务内 max+1。
- 界面标注「自动产生」，与截图一致。

## 4. 核心校验

### 4.1 新建 / 保存草稿 / 提交前（发起拦截）

对目标 `emp_id`：

1. 若存在 `status = InReview`（且非本单）→ 拒绝（R8）。
2. 若存在 `status ∈ {Draft, InReview, Approved, Effective}` 且 `chg_date > 本次 chg_date` → 拒绝（R9）。
3. 若存在同员工、同 `chg_date`、拦截状态内的其它单 → 拒绝（同日仅一张）。
4. 同一员工在拦截状态内最多一张 `Draft`（不含本单）。

换人、改异动日期时重跑上述校验。

**草稿加载**：Detail 返回已存明细；默认不按主档覆盖。`PreviewDefaults` / `reloadFromEmp` 仅用于新建选人、换人、或用户点击重载。

### 4.2 提交

- 状态必须为 `Draft`。
- 工号、异动日期、异动类别、明细非空。
- 明细 `field_key` 集合须与**当前启用配置**一致（可多不可缺启用项；停用项若仍留在草稿中则提交失败并列出差异）。草稿保存允许暂与配置不完全一致，提交时严格校验。

### 4.3 通过 / 驳回

- 仅 `InReview`。
- 权限：审核按钮（非发起人角色校验可二期再加「不能审自己」）。
- 通过 → `Approved`；若 `chg_date ≤ 今天`，触发一次写回尝试。
- 驳回 → `Rejected`，可填原因。

### 4.4 写回（Apply）

前置：`status = Approved` 且 `chg_date ≤ 业务日（当天）`。

事务内：

1. 锁异动单行；再读员工主档。
2. **不校验**主档当前值是否仍等于 `value_before`；直接按明细将 `value_after` 转为列类型写入 `h_emp_mstr`（覆盖期间人工或其它途径的改动）。
3. 更新单 `Effective` + `effective_time`。
4. 写日志。

失败保持 `Approved`，任务下次重试；需可观测（日志/任务监控）。

说明：`value_before` / `value_after` 在开单保存时冻结；写回与撤销都只认单据快照，不重读「当时主档」来改快照。

### 4.5 撤销（Void）

前置：

- `status = Effective`。
- 不存在同员工、`chg_date` 更大、且 `status ∈ {Draft, InReview, Approved, Effective}` 的单据（建造方默认，防打穿时间线）。

事务内：

1. 按本单明细把主档字段写回 `value_before`。
2. 单改 `Voided`，记撤销人/时间/原因。

## 5. 值读写约定

| 控件/类型 | 存储 | 写回 |
|-----------|------|------|
| 文本 | 原样 | 原样 |
| 日期 | `yyyy-MM-dd` | 解析为 date |
| 数字 | 不变文化数字串 | 解析 |
| 代码下拉 | 存代码值 | 写代码值 |
| 部门 cascader | 存 `cc_code` | 写 `CcCode` |

展示层：异动前只读可用描述（如部门名），但**落库与写回以代码/主键值为准**；描述可运行时解析，不必另存一列（需要快照时再加 `*_text`）。

选人后加载默认值：走员工 Detail/DTO，按 `field_key` 反射或白名单字典取值（与 `HrEmp` 属性 camelCase 对齐）。

## 6. API 要点（建议）

服务名示例：`HrEmpChgService`、`HrEmpChgFieldService`。

| 接口 | 说明 |
|------|------|
| 配置 Page / Save | 维护 `hr_emp_chg_field`；Save 时校验字段池 |
| 配置 GetEnabled | 开单用启用列表 + 池上控件元数据 |
| 异动 Page | 继承 `BasePageInput`，`OrderBuilder` |
| Detail | 主表 + 明细 |
| SaveDraft | 新增/更新草稿；重算默认值可选参数 `reloadFromEmp` |
| DeleteDraft | 仅 Draft |
| Submit | Draft → InReview |
| Approve / Reject | InReview |
| Void | Effective → Voided + 回滚 |
| PreviewDefaults | 工号 + 可选日期 → 返回表体默认前/后 |

权限：`HrEmpChg:Add|Update|Delete|Submit|Approve|Reject|Void|FieldConfig`（命名实现时与项目惯例对齐）。

## 7. 定时任务

| 项 | 建议 |
|----|------|
| 类型 | `Furion.Schedule.IJob`，`Concurrent = false` |
| 频率 | 每 5～15 分钟，或每日多次；避免仅每天一次导致「当日下午通过且日期已到」久等 |
| 逻辑 | 查询 `Approved && chg_date <= today`，逐单调用写回（单笔事务，互不影响） |
| 运维 | 任务失败进系统日志；必要时企微/现有 JobMonitor |

## 9. 验收用例（最小集）

1. 配置仅部门 → 开单左右均显示当前部门，改「后」并保存草稿。
2. 同人已有审核中单 → 再开失败。
3. 同人已有 10-25 的生效/待生效/草稿 → 再开 10-20 失败；开 10-26 成功。
4. 提交 → 通过 → 改系统日或等任务 → 主档 `cc_code` 变为异动后；单为已生效；明细不可改。
5. 撤销 → 主档恢复异动前；单为已作废；可再开新单。
6. 已生效后存在更晚单据 → 撤销早单被拒绝。
7. 驳回后同人可再开新单。
