## 1. 结论先说

`03` 已立住骨架：**组织归属 ≠ 业务管辖；管辖按 Domain（业务域）拆；同域内用 Population（人员分群）**。  
本文不再重讲骨架，而是把市面 HCM（人力资本管理）**全业务域**摊开，给每个域标定：

| 标定项 | 含义 |
|--------|------|
| **Domain 建议码** | 进 `UserBizScope.Domain`（用户业务管辖.业务域）的枚举候选 |
| **过滤主锚点** | 该域列表/作业池默认按什么筛「人」 |
| **常见分群** | Population（人员分群）条件 |
| **与人事关系** | `OwnDomain`（本域自有）/ `InheritPersonnel`（继承人事）/ `CrossCut`（横切）/ `NoEmpScope`（无员工管辖） |
| **本产品优先级** | P0～P3 / 远期 / 可不独立成域 |

**总原则（与市面一致）**：

1. 凡「作业池里看见哪些员工/候选人/编制位」→ 必须挂 Domain（业务域，或显式继承）。  
2. 凡「主数据代码/参数/表单定义」→ 通常走菜单权限，**不必**员工级管辖。  
3. 凡「审批找人」→ 与作业管辖正交（汇报链 / 角色树 / 等级），见 §5。  
4. 域可以很多，**配置面要收敛**：管理员先配人事，其它域默认继承，直到现场需要拆开。

## 3. 业务域全景表（不漏域）

> **过滤对象**列：管辖作用在「哪类主体」上（多数是在职/历史员工；招聘是候选人；编制是岗位/坑位）。  
> Domain 码中文见 **§0.4**；表内简称：**Own**＝本域自有管辖。

### 3.1 核心人事与组织（Core HR）

| 市面模块 | Domain 建议 | 过滤对象 | 推荐主锚点 | 常见分群 | 与人事 | 优先级 |
|----------|-------------|----------|------------|----------|--------|--------|
| 员工主档 / 人事档案 | `Personnel` 人事 | 员工 | 行政组织 `CcCode` + 含下级 | 用工类型、员工状态、职级、厂别 | **本域** | **P0** |
| 入职 / 转正 / 调岗 / 离职等异动 | `Personnel` 人事 | 员工（或入职单上的拟入职人） | 同人事；拟入职可用拟入部门 | 异动类型 | 同人事 | **P0** |
| 劳动合同 / 协议 | `Personnel` 人事（或子域 `Contract` 合同） | 员工 | 行政组织；合同主体公司可作二次条件 | 合同类型、主体公司 | 默认同人事；多法人强诉求再拆 | P1 |
| 电子档案 / 证件附件 | `Personnel` 人事 | 员工 | 同人事 | 密级（常另控功能权限） | 继承 | P1 |
| 组织架构维护 | `NoEmpScope` 无员工管辖 | 组织节点 | **不做员工过滤**；节点编辑权可用「可维护组织范围」另表 | — | 与员工管辖分开 | P1 |
| 岗位 / 职务体系 | `NoEmpScope` 无员工管辖 | 岗位主数据 | 菜单+是否按公司隔离 | — | 非员工池 | P1 |
| 编制占用 / 坑位 | `Headcount` 编制 | 编制位/岗位需求 | 行政组织或编制单元 | 编制类型、职级段 | **Own** 本域；弱场景可继承人事组织 | P2 |
| 组织人数 / 人事报表（作业侧） | `Personnel` 人事 或 `Report` 报表 | 员工 | 见 §3.8 | — | 见报表 | P1 |

**员工多归属（主数据，支撑其它域，非 Domain 本身）**：行政组织、发薪主体、考勤组织、成本中心、直线经理/HRBP（人力资源业务伙伴）——定义见 `03` §4.2。

### 3.2 劳动力与假勤（Workforce 劳动力 / Time 工时）

| 市面模块 | Domain 建议 | 过滤对象 | 推荐主锚点 | 常见分群 | 与人事 | 优先级 |
|----------|-------------|----------|------------|----------|--------|--------|
| 打卡 / 考勤日结 / 异常处理 | `Attendance` 考勤 | 员工 | **考勤组织 / 考勤组 / 考勤点**（无则回退行政） | 班制、车间、厂区 | **Own** 本域；过渡期 `InheritPersonnel` 继承人事 | **P1** |
| 请假 / 销假 / 调休账户 | `Attendance` 考勤 或 `Leave` 假勤 | 员工 | 同考勤组织；部分企业按行政 | 假别权限另走功能 | 常与考勤同域 | P1 |
| 加班申请与确认 | `Attendance` 考勤 | 员工 | 同考勤 | 计时/计件 | 同考勤 | P1 |
| 排班 / 调班 / 值班 | `Attendance` 考勤 或 `Scheduling` 排班 | 员工 | 考勤组织/产线 | 班组 | Own 本域 | P2 |
| 劳动力优化 / 工时分析作业 | `Attendance` 考勤 | 员工 | 同考勤 | — | 同考勤 | 远期 |

市面常把 Time Off（休假账户）与 Time Sheet（工时填报）拆开，**管辖上多数仍共用同一套工时安全组织**；仅当「假勤专员 ≠ 考勤异常专员」普遍时再拆 `Leave`（假勤域）。

### 3.3 薪酬与福利（Payroll 薪酬 & Benefits 福利）

| 市面模块 | Domain 建议 | 过滤对象 | 推荐主锚点 | 常见分群 | 与人事 | 优先级 |
|----------|-------------|----------|------------|----------|--------|--------|
| 薪资档案 / 月度算薪 / 发放 | `Payroll` 薪酬 | 员工 | **发薪主体** + **薪资组** | 计时计件、干部/工人、外包 | **Own** 本域 | **P1～P2** |
| 个税申报作业 | `Payroll` 薪酬（或 `Tax` 个税） | 员工 | 发薪主体/扣缴义务人 | — | 默认同薪酬 | P2 |
| 社保 / 公积金缴纳作业 | `Benefits` 福利 或并入 `Payroll` 薪酬 | 员工 | **参保主体 / 社保账套**（可 ≠ 发薪主体） | 险种方案、户籍类型 | 强诉求 Own 本域；弱则并薪酬 | P2 |
| 福利商城 / 补贴方案资格 | `Benefits` 福利 | 员工 | 资格规则（公司+人群） | 司龄、职级 | 可 Population 人员分群为主 | 远期 |
| 年度调薪包 / 奖金分配（Compensation Planning 薪酬规划） | `Compensation` 调薪规划 | 员工 | 常按**组织+预算单元**或经理树；≠ 月薪算薪池 | 职级、绩效结果 | **Own** 本域；与 `Payroll` 薪酬分离 | P3 |
| 成本中心分摊结果查询 | `Payroll` 薪酬 / `Report` 报表 | 员工或凭证 | 成本中心或发薪主体 | — | 按报表策略 | P2 |

**红线（市面共识）**：月薪作业范围用「薪资组×发薪主体」；调薪包常用「预算组织/经理」——二者不要强行同一套树。

### 3.4 人才获取（Talent Acquisition）

| 市面模块 | Domain 建议 | 过滤对象 | 推荐主锚点 | 常见分群 | 与人事 | 优先级 |
|----------|-------------|----------|------------|----------|--------|--------|
| 招聘需求 / 职位 | `Recruiting` 招聘 | 需求/职位 | **需求所属组织** 或招聘区域 | 职位族、社招/校招 | Own 本域；早期可按创建人+功能权限 | P2 |
| 候选人库 / 面试评价 | `Recruiting` 招聘 | 候选人 | 关联职位的组织范围；或招聘团队私有池 | 渠道、阶段 | Own 本域 | P2 |

| 市面模块 | Domain 建议 | 策略 | 优先级 |
|----------|-------------|------|--------|
| 运营报表（专员日常） | 跟随源业务域 | 考勤报表用 `Attendance` 考勤，薪酬用 `Payroll` 薪酬 | P1 |
| 管理驾驶舱 / 董事会包 | `Report` 报表宽域或超管 | **禁止**被一线作业窄管辖误伤；单独只读角色 | P2 |
| People Analytics（人力数据分析）平台 | `Report` 报表 | 行级安全按主题选锚点（组织/公司） | 远期 |

### 3.9 平台与主数据（通常不成「员工管辖域」）

| 能力 | 建议 | 说明 |
|------|------|------|
| 码表 / 多语言名称 / 字段与布局定义 | `NoEmpScope` 无员工管辖 | 菜单功能权限；公司级隔离另议 |
| 公司参数 / 厂别参数 | `NoEmpScope` 无员工管辖 | 按可维护 `SiteCode`（厂别码）列表控（非员工池） |
| 审批流程定义 / 表单模板 | `NoEmpScope` 无员工管辖 | 定义权 ≠ 审批时可见员工范围 |
| 消息通知模板 | `NoEmpScope` 无员工管辖 | — |
| AI 助手 / 聊天机器人 | 跟随调用的业务 API Domain（业务域） | 无独立员工树 |

## 4. Domain（业务域）枚举收敛（防配置爆炸）

市面模块 **≠** 必须一对一建 Domain。推荐本产品 **一级 Domain** 收敛如下：

| Domain 码 | 中文 | 覆盖的市面模块（合并） | 默认策略 |
|-----------|------|------------------------|----------|
| `Personnel` | 人事 | 档案、异动、合同、电子档案、人事类证明 | Usercc 用户人事管辖 · 行政树（P0） |
| `Attendance` | 考勤 | 打卡异常、假勤、加班、排班 | 考勤组织；可 InheritPersonnel 继承人事 |
| `Payroll` | 薪酬 | 算薪、个税、（弱）社保 | 发薪主体×薪资组 |
| `Benefits` | 福利 | 社保公积金、福利资格（与薪酬主体常不一致时启用） | 参保主体；否则并入 Payroll 薪酬 |
| `Recruiting` | 招聘 | 需求、候选人、面试 | 职位/需求组织 |
| `Performance` | 绩效 | 目标绩效 | 默认可继承人事 |
| `Learning` | 学习 | 培训学习 | 默认可继承人事 |
| `Compensation` | 调薪规划 | 调薪包/奖金分配 | 与 Payroll 薪酬分离 |
| `Succession` | 继任盘点 | 盘点继任、干部 | 敏感宽/窄单独配 |
| `Headcount` | 编制 | 编制坑位 | 组织/编制单元 |
| `Report` | 报表 | 宽域只读分析 | 独立角色 |
| `MssTeam` | 经理自助 | 经理看下属 | 汇报树 |
| `EssSelf` | 员工自助 | 本人 | 固定 |

**可选延后、不进一级枚举**（中文见 §0.4）：`Leave` 假勤、`Scheduling` 排班、`Onboarding` 入职办理、`Tax` 个税、`WorkforcePlan` 人力规划、`Engagement` 敬业度、`Ehs` 健康安全、`Mobility` 外派、`Contingent` 外包工——优先用合并域 + Population（人员分群），待现场撕裂再升格。

**永远建议独立于员工 Domain**：组织节点维护范围、公司参数可维护厂别、流程定义权。

## 5. 横切能力：不要塞进业务 Domain

| 横切 | 市面做法 | 与本方案关系 |
|------|----------|--------------|
| 菜单/按钮/API | 角色功能权限 | 已有；与数据范围求交 |
| 审批人解析 | 汇报线、岗位角色树、等级、指定人 | **审批可见/可批** ≠ 专员作业池；P3 与 `03` 一致须分离 |
| 字段级脱敏 | 角色/职级/自助 | 不替代组织管辖 |
| 超管 / 全部数据 | 跳过 Domain（业务域） | 保留 |
| 审计日志 | 谁在何时看见/导出 | 分群与宽域报表必备 |

## 6. 与 `03` 分期的衔接（全景视角）

| 期 | `03` 原焦点 | 全景补强（本文） |
|----|-------------|------------------|
| **P0** | Personnel 人事 = Usercc 用户人事管辖 | 明确合同/档案/异动均挂 `Personnel`；组织维护≠员工管辖 |
| **P1** | 发薪主体、考勤组织、Inherit（继承）开关 | 落地 `Attendance`/`Payroll` 策略；报表跟随源域；ESS 员工自助本人 |
| **P2** | UserBizScope 用户业务管辖 + Population 人员分群 | 启用 `Benefits` 福利（若社保≠发薪）、`Recruiting` 招聘、`Performance`/`Learning` 继承或 Own 本域、MSS 经理自助汇报树、外包 Population |
| **P3** | 职责包、SSC 共享中心、审批与作业分离 | `Compensation` 调薪规划、`Succession` 继任、`Headcount` 编制、`Report` 报表宽域、SSC 并集 |

**非目标**：为每个市面子模块建一张管辖表；把 ESS/MSS（员工/经理自助）/审批硬塞进行政 Usercc；用一套行政树推导招聘候选人与董事会报表。

## 7. 实施检查清单（按域验收）

新模块上线前勾选：

- [ ] 模块是否处理「人/候选人/编制位」列表或写操作？是 → 必须声明 Domain（业务域）或 `NoEmpScope`（无员工管辖）理由  
- [ ] 过滤主锚点是否写进方案（行政 / 考勤 / 发薪 / 职位组织 / 汇报树 / 本人）？  
- [ ] 默认 `InheritPersonnel`（继承人事）还是 `OwnDomain`（本域自有）？是否在管理员界面明示？  
- [ ] 需要 Population（人员分群）的分群字段是否在主数据存在？  
- [ ] 审批流是否误用了作业管辖？  
- [ ] 报表是跟随作业域还是宽域只读角色？
