# 离职/复职管理 — 数据模型与接口要点

> 配合 [02-需求与方案总览.md](./02-需求与方案总览.md)  
> 一期：**独立业务表 + 模块内审核 + 本模块 Apply/Job**；不依赖流程 Handler 正式入口。  
> 2026-11-10：`hr_emp_leave_restore` 同时承载 **同工号复职单**（`kind=Reinstate`）与 **离职纠错审计**（`kind=Correct`）。

---

## 1. 状态机

与异动相同：`Draft` / `InReview` / `Approved` / `Effective` / `Rejected` / `Voided`。

- 离职计划生效日 = `leave_date + 1`  
- 复职计划生效日 = `restore_date`（**当日**）

---

## 2. 表

库：HR 业务库。

### 2.1 `hr_emp_leave` 离职单

| 列 | 说明 |
|----|------|
| leave_no | 单号 `LV`+yyyyMMdd+流水 |
| emp_id / emp_name | |
| leave_date | 最后在职日 |
| plan_effect_date | leave_date+1，开单时写入 |
| leave_type / leave_reason / salary_settle | 码表 |
| is_blacklist | 0/1 |
| cc_code_snap | 开单时部门快照（管辖校验） |
| emp_state_before | 生效前状态 |
| status / 审核撤销字段 | 同异动 |
| remark | |

### 2.2 `hr_emp_leave_restore` 复职单 / 纠错审计

| 列 | 说明 |
|----|------|
| restore_no | 复职 `FZ`+yyyyMMdd+流水；纠错审计 `LR`+yyyyMMdd+流水 |
| **kind** | `Reinstate` 同工号复职；`Correct` 离职撤销写入的纠错审计 |
| leave_id / leave_no | 纠错审计关联原离职单；复职单一般为空 |
| emp_id / emp_name | **同工号**，不新建主档 |
| restore_date / plan_effect_date | 复职日；计划生效日=复职日 |
| clear_blacklist | 复职可选清黑名单 |
| remark | |
| status / 审核撤销字段 | 同异动 |
| operate_* | 纠错审计操作人时间（Correct） |

复职列表 API 默认 `kind=Reinstate`，不展示纠错审计。

### 2.3 `hr_emp_leave_pay_cmd` 薪资结算指令

| 列 | 说明 |
|----|------|
| leave_id / leave_no / emp_id | |
| leave_date / settle_code | |
| pay_period | yyyyMM（一期按离职日自然月） |
| status | Active / Consumed / Voided |

### 2.4 主档

- `emp_state`：离职生效→3；**复职生效→1**（同工号）  
- `emp_lea_date`：存**离职日**；复职清空；撤销复职时尽量还原最近 Effective 离职日  
- `emp_beg_date`：复职生效写**本期到职日**=复职日；**保留** `emp_in_date` 首次入职日  
- `emp_black`：黑名单 0/1；复职勾选才清  

---

## 3. API（`hrEmpLeave` / `hrEmpLeaveRestore`）

- 离职：Page（含 `statusList`）/ Detail / SaveDraft / DeleteDraft / Submit / Approve / Reject / Void  
- 复职：同上；Page 默认 `kind=Reinstate`，支持 `statusList`  
- 选人：工号输入 `hrEmp/lookupByEmpId`（管辖精确匹配）  

---

## 4. Job

`HrEmpLeaveApplyJob`：每日扫描 `Approved` 且 `plan_effect_date≤今天` 的离职单与 **kind=Reinstate** 复职单。
